# 多人军师（基于官方 0.43.2）

当前源码为本地准备版 [0.43.6](releases/0.43.6-RELEASE_NOTES.md)，修复死亡队友重算及效果生命周期；GitHub 已发布版本仍为 [0.43.5](releases/0.43.5-RELEASE_NOTES.md)。分支合入官方 `3f4002bd / 0.43.2`，包含完整当前回合覆盖后的长线比较、多人遗物归属与佩尔之眼修复。上限十四个敌方周期，普通手动请求时间/节点上限仍为原值两倍；单人保持该官方版本路径。官方标签不含 fork 多人功能。原始研究与历史版本见[策略索引](strategy/README.md#多人研究归档)，上游兼容见[合并记录](strategy/upstream-0432-merge-20260920.md)，长线策略见[实施归档](strategy/pro-window-selection-20260920/implementation.md)，渠道凭证见[发布归档](releases/0.43.5-PUBLISH.md)。真实联机尚未验收。

## 使用方式

- 主机或客户端均以本机玩家为决策者，不假定玩家列表第一位就是自己。
- 发牌和回合开始选择完成后，按「重新计算」捕获当时的整个战场。只有这个按钮发起重算；新回合、自己或队友的操作不会自动重算。
- 尚有动作/选牌在结算时显示等待提示，完成后继续这次手动请求；启动失败会显示原因。`0.40.3` 出现点击完全没有反馈时，升级到 `0.40.4` 并重启游戏。
- 多人面板隐藏执行、全自动、自动计算和采纳入口；停止按钮保留当前候选，尚无新候选时保留上次完成的建议。后台只模拟，不替任何玩家出牌、用药、结束回合或选牌。
- 队友行动后旧建议仍保留，显示「战场已变化」。再次按重新计算会取消并等待旧搜索退出，再捕获稳定的新局面。结束战斗会清理搜索和建议。
- 队友死亡后，等待死亡结算完成仍可手动重算。完整保存死亡队友的残留能力和物品，按游戏的停用状态排除其效果；复活后恢复生效。死亡时保留能力不再导致根捕获失败，死亡队友也不再产生佩尔之眼额外回合。证据与限制见[死亡队友验证](TEST_MATRIX.md#0436fork死亡队友重算2026-09-21)。
- 药水加入每个合法动作节点的搜索，包含使用时机、玩家/敌方目标和本人的选牌；保护及强制用药设置继续生效。多人不套用单人额外的省血门槛审计。
- 多人不采用单人的局外成长额度；疯狂科学的改进效果正常归属于持有者，但不因此扩大多人战损目标。读取整场历史的牌继续按原效果的玩家范围统计，单人的增量计数优化不借用任何队友身份。
- “至少用一瓶”只认可原战斗追踪窗口内本机的已用药记录；队友用药或给本机投药不解除本机要求。本机先前已用药时继续沿用原规则，不要求每次手动重算再喝一瓶。
- 遗物提示标注「自己」或「队友编号」。结束回合建议也会列出随后结算的队友被动；例如「队友 1：佩尔之眼：额外回合」只表示队友获得额外回合，不表示本机可以再出牌。不同玩家的同名遗物分别显示。

## 推演假设与取舍

搜索默认最多覆盖十四次敌方行动周期；额外玩家回合不消耗这个窗口。普通多人请求的时间和节点上限均为性能设置值的两倍，例如默认中档从 120 秒 / 120,000 节点变为最多 240 秒 / 240,000 节点；这是停止上限，不要求每次等满。Beam 宽度、并行度和内存配置不增加，单人设置不被改写。显式固定测试预算或时间覆盖保持原值，不再乘倍数。搜索按当前前沿尚未完成的敌方周期分摊剩余预算，额外玩家回合不算已完成周期；原单层最低额度和全局停止条件继续生效。

面板分别显示路线实际推演深度、十四周期上限与选路共同周期，详情显示本次实际时间和节点上限。预算不足时仍可提前返回，不保证每次完成十四周期，也不保证一回合建议拥有已验证的十四周期后续。首个敌方周期尚未完成时明确提示缺少完整受击评估。Beam 是有界启发式搜索，不承诺全局最大伤害。

[2026-09-19 窗口研究](strategy/pro-horizon-20260919/README.md)保留七周期之外的延迟收益和队友提前击杀令投资落空的反例。[十四周期对照](strategy/multiplayer-fourteen-cycles-20260920.md)随后采用 H=14、双倍请求额度和按剩余敌方周期分摊。本轮调整的是已有候选的比较时点，上限仍固定十四，不按未知队友行为估计战斗时长。全终局池的共同周期字段可能取上限作哨兵，实际完成深度看路线自身。

按用户确认的多人打法，每个敌方周期以本机扣血不超过 3 HP 为目标，优先避免本人死亡，再比较救命资源消耗和超额扣血；同等风险下优先真实胜利和保住队友，再压低敌人剩余生命。当前救命资源按全队次数汇总，尚不能独立比较本机与队友的消费，且该次数排在本机超额之前；这是[本轮复审确认的口径限制](strategy/pro-review-20260918/local-review.md#r3全队资源观察与本机风险)，调整优先级尚未实施。输出相同时少扣血，相同收益时少用药。没有满足额度的路线时仍会给出超额较少的建议。路线比较使用已经完成的共同周期，搜索更深本身不加分；具体续行后来出现的死亡、复活消耗、超额或队友死亡仍作为反证，不能藏回较早的安全检查点。

3 HP 按每个敌方周期分别计算，不是十四周期共用的 42 HP。使用本机实际未格挡扣血，包含自损以及手动计算前本轮已经支付的部分；治疗不抵扣已用额度，重新计算和额外玩家回合也不刷新。下一玩家回合开始的自损属于新的周期。面板会显示扣血目标与当前预测中最高的单周期扣血，供玩家决定是否采用。

### 未击杀时如何选择长线方案

先按原资格得到旧共同周期结果 A。在既有预览与最终选路点，C 按完整当前本机回合的牌序、实例、目标、药水槽和选择建立代表；范围包括截断前的候选、仍保留的已结束回合和上一层候选。它只代表当前有限搜索还保留的方案，不覆盖全部合法牌序。未完成本回合或必要用药的活动前缀、未完成首个敌方周期、外部选择、未支持边界和超过 Beam 的代表数量都阻止升级。

每个代表必须至少有一条实际生成、完整受击后的续行。取各代表最深证据的最小值，只有该值比 A 更深时才统一在这个周期比较。浅代表没有后续就沿用 A；不删除它来制造全部覆盖，也不另开搜索补到十四周期。同一具体路径的可见延长会替代其旧祖先，但不会连带排除同本回合的其他好续行。

C 沿用本人存活、可比较性、救命资源、超额、胜利、队友存活、敌方剩余有效生命、扣血、本人生命、用药的原顺序；完整后缀已出现的死亡/消耗/超额/队友死亡仍参与比较。仅 C 末级同分项取共同周期边界处的动作数，完整终局仍取全路线；A 和中间保路继续使用原完整动作数。C 选中路线的已知本人死亡、救命次数、超额等级若劣于 A，返回 A。名义格挡、未来能力估值和更长展示不作为终局收益。

元数据只在本次发布内存在，上限 65,536 个字符/节点/排序计费单位；它是工程工作上限，不是新增搜索节点。扫描与最终路线、续用前缀重放的估算费用消费原请求剩余时间，取消照常传播；耗尽则返回 A。重放估算使用本请求平均转移耗时并留两倍系数，不是严格墙钟保证。诊断 `MULTIPLAYER_WINDOW` 记录应用/回退原因、A/C 周期、代表数量、待满足资格、祖先数和扫描费用，不新增玩家设置或跨请求分数缓存。

长线比较可能牺牲早期伤害；队友改变目标、阶段或战斗长度也可能令铺垫失效。本轮晚回本样例第 3/7/14 周期伤害为 A 的 21/49/98 对 C 的 18/54/117；另一个真实来伤样例首动作不变。它们不构成普遍增益或十四周期安全保证。

所有玩家的血量、格挡、资源、牌堆、药水、能力、遗物、球、怪物状态及 RNG 从当前战场冻结。未来假设队友不再主动出牌/用药，但照常处理其回合阶段、被动效果、抽牌和受击。因此这是一条有条件的建议，不是队友未来行为的预测，也不把未知的队友输出算作已造成伤害。

佩尔之眼按各自持有者结算：未参加队友额外回合不算作自己空过回合；自己的其他效果给予额外回合时，也按游戏规则消耗自己的佩尔之眼。仅队友参加的额外回合由模拟自动跨过，本机动作仍等到自己的可操作回合。

需要队友选择时明确停止在「等待队友选择」边界，包括向队友投掷需要选牌的药水；不替队友决定。未支持效果形成明确边界。玩家列表中的目标带编号，重复职业也能区分。

## 复用与单人隔离

每次搜索继续使用现有分支 Fork、完整状态去重、转置表、选牌前缀、并行展开和预算控制。多人状态键补充所有队友的可变状态；只描述单人效果的动作支配/小型 Pareto 不能据此淘汰多人分支。

多人保路在既有 Beam 内先覆盖防御、进攻和铺垫代表，再补剩余名额；不另外开树或追加预算。单周期扣血账本归属搜索节点，原始周期观察使用至多十四条不可变短链。同一战斗状态但已用额度、此前超额或比较检查点不同的路线由去重和转置标签区分；这些政策历史不进入战斗状态键或原生对账戳。

跨次最多保留四条路线的纯动作数据，每条最多重放当前回合的 32 个无选择动作。旧动作在新根上重新检查牌实例、费用、目标、药水指令并重新模拟，之后作为候选起点；不保留旧树、旧分数、旧影子对象，也不强制采用旧路线。非法首步不复用，遇到选择或回合结束便停止前缀复用。复用工作计入当前请求节点及转移统计。

这能让已找到的合法动作组合较早参加比较，但没有证明总耗时一定下降；这里不报告提速倍数。本人已经执行旧路线前缀时暂不自动匹配剩余后缀，也没有跨不同状态直接返回缓存结果。

多人策略由 `MultiplayerSearchPolicy` 注入，Runtime 不修改持久化的单人自动计算设置。多人绕开单人磁盘路线恢复、反事实用药审计、局外收益目标和自动部署。既有单人分支与比较器保持原路径。

## 首批策略优化（已实施）

2026-09-17 根据用户提供的[策略研究原文](CombatSolver_Multiplayer_Strategy_Research_and_Design.md)，从兼容合并 `7160d2f` 实施三步改进。原研究基线 `f220a6b / 0.40.5` 保留历史语境；本批单人对照为官方 `0e6cc2d / 0.41.0`。继续复用 Beam、合法动作展开、全队模拟和请求预算，新增一个多人评估分片与一个纯值记录，没有第二套 Planner、残值接口、长期树或策略版本开关。

### 保路配额

先取得防御、进攻、铺垫各自的代表。同一候选覆盖多个类别时不再为重合类别强取第二名；覆盖代表后才轮流补充，最后按原多人总榜填满。

- Beam 至少为 4：保留总榜第一与三类代表；重合不多占位置。
- Beam 为 3：优先三类代表，不额外承诺第四个总榜候选。
- Beam 为 2：保留总榜第一，另一个名额按候选的稳定动作深度轮换，不使用随机数或跨请求状态。
- Beam 为 1：只保留总榜第一。没有合格存活代表时按总榜补位。

配额只保护探索机会，不保证特定首动作一直保留。既有防御通道仍可用格挡作为探索特征；最终结果不因格挡数字大而获奖。

### 共同周期与已知风险

`Expansion` 在敌方周期结算完成、下一玩家准备阶段之前记录周期、本人 HP/累计扣血、复活消耗、有效敌方 HP、存活人数和用药数。不可变记录引用此前周期，Fork 可共享历史；没有额外模拟器或战斗状态副本。账本继续把根已付扣血计入第一周期、把下一开始阶段自损计入新周期。

原共同周期流程 A 先从完整发布池筛选满足用药要求的路线，再确定最浅的已完成周期并裁剪候选；当前预览和最终返回还会按[完整回合覆盖条件](#未击杀时如何选择长线方案)尝试 C。一次选路从裁剪到选择、结果深度元数据都使用同一个批次上下文。真实提前胜利/死亡是终局，外部选择和未支持边界不是；无法完成共同周期的路线不与已完整受击评估的路线冒充同等证据。全部候选都被阻断时仍可报告最后观察及其边界。比较器不会为每一对候选临时换深度。

0.41.1 曾在截断后才检查“至少用一瓶/最少显式用药”，并在子集上重建共同周期。[复审与本地核对](strategy/pro-review-20260918/local-review.md)保留原始发现；2026-09-18 按用户指令实施第一批修正，并随后定版为 0.41.2。已终止的候选在中途压缩时也先检查资格；仍能继续展开的未用药前缀不因最终要求被提前排除。没有合格结果时继续明确报告用药条件未满足。资源归属、默认风险顺序与两步挑战不属于这次修正。

预算停止时保留上一回合层的有界候选组，供最后一次共同周期比较。只留已释放模拟器的节点与数值，选中的路线由现有结果物化流程重放，转移仍计入原请求统计。首周期未完成时仅提供带明确提示的未完成建议，不把未来来伤填成零；已返回的短前缀也不代表后续十四周期安全。

共同边界内依次考虑逐槽强制药水满足情况、本人实际死亡、证据完整性、全队救命次数、逐周期超额、真实胜利、队友存活、敌人生命、本人扣血/余血和药水。同一路线在更后面已经发生的死亡、救命消耗、超额或队友死亡仍参与风险判断；不能用它较早的安全观察掩盖。这个反证只否定具体续行，不封禁同首动作的其他合法路线。尚未展开的未来仍然未知。

其他事实相同时，A 和中间比较仍使用完整路线的动作数作为末级同分项。[2026-09-19 窗口研究](strategy/pro-horizon-20260919/README.md)当时只做共同周期动作成本的离线实验，`0.41.3` 未纳入；`0.43.4` 仅在 C 完整覆盖且严格升级周期后采用。两种策略都不能把末级同分变化记为战斗收益。

[第二轮复审首批修正](strategy/pro-review-0412-20260918/implementation.md)已让真实胜利/死亡使用完整终局事实，只有未结束路线才回看共同周期；没有把胜利提到本机死亡、救命资源或已知超额风险之前。多人也不再因池中存在一条本机无损满血胜利而提前停止，仍受原预算和窗口约束，因此可能比旧版使用更多原有搜索额度。根前用药输入按本机归属修正，最终资格过滤本身不重复增设规则。

完成池局部压缩与最后联合比较仍可能使用不同候选集合；末父节点的已付卡牌候选和旧当前回合预览旁路继续保留研究期限制。共同周期外动作数在 A 中仍可影响末级同分，C 的适用范围见现役说明。默认全队救命次数与风险次序保持原样。其余条件、未验证范围和暂缓理由见[此前实施记录](strategy/pro-review-0412-20260918/implementation.md#保留的条件项)。不能把已发布修复理解为所有入口已完备或联机策略已最优。

### 有效防御、救援与铺垫

删除按全部怪物名义攻击总和计算的格挡加分，直接使用已经结算的周期事实。同等本人风险下，保住队友先于多打少量伤害；无效、过量或给错受击对象的格挡没有单独的终局奖励。已有减伤、抵销与攻击目标继续由模拟器真实结算，没有逐动作新增探针或复制单人 StandPat 的假设。

能力与牌流估值仅用于中间保路，最终共同周期不奖励未兑现的铺垫。短窗口适合直接输出，后续周期确实能兑现的能力路线才可能胜出；依赖真人队友主动配合或未知选择的收益不提前计入。保护/强制药水指令、每周期 3 HP、本机手动重算保持既有合同；现上限十四周期，选路升级条件见上方现役说明。

`FOGMOG_NORMAL` 使用同样的 Beam 12、350 节点、12 秒预算、DOP 2；为让无主动操作的双方活到窗口末尾，合同在建局后把双方生命及上限设为 500。全部预测先从同一个冻结根生成，再推进原生战斗：

- 前六个完整回合的双方有序牌堆、能力、历史、怪物状态、生命、资源和九条 RNG 与原生全文对账一致；第七个敌方回合在窗口边界停止。
- 同根的五回合政策在第五次停止，七回合政策此前继续；额外玩家回合仍不增加敌方周期数。
- 正式搜索在原预算内返回 23 个动作、七回合建议；有效旧路线重新验证 1 个动作，非法实例前缀拒绝。此输入与前一阶段生命值不同，不比较耗时或路线优劣。
- 仅允许 1 个展开节点的请求按节点边界提前返回；界面投影显示实际推演次数与七回合上限，英文模板正常解析。
- 四张多人卡牌、队友药水、生成药水原生结算、本人选牌增量等价、队友选择边界、强制/禁用药水与禁止自动操作合同均通过。

此次产物为 `.local/mp-seven/` 与 `.local/mp-seven.log`，合同步骤耗时 5.112 秒；其中含原生对照及多次搜索，不作为单次搜索性能数字。

最终单人哨兵沿用独立编译的 `8411164` 基线，只重跑当前实现：61 项非时间/分配指标、9 个动作、根状态与目录字段共 72 项再次全部一致，仍为 126 节点、376 转移、T3 胜利、4 HP 累计损失。产物 `.local/solo-seven/`、`.local/solo-seven-comparison.json`。结构化证据 `MULTIPLAYER-ADVISOR-MANAGED-CONTRACTS` 和 `MULTIPLAYER-ADVISOR-SOLO-SENTINEL` 记录在 `coverage/test-evidence.json`，没有把局部合同登记成所有多人内容已验证。

主项目与离线宿主 Release 编译均为 0 警告/0 错误；Bash 结构门禁通过，`search_files=118`。补齐了前一任务漏登记的两个多人搜索分片，两端文件清单与 7 条多人规则一致。440 项本地化模板的占位符相同。本机未安装 PowerShell，未执行 Windows 入口。

`CoverageCatalog --verify-effective --verify-state-fields --verify-branch-state-reads` 通过：现有 3035 项目录无待实现、live 分支读取或未分类状态字段。工具原默认 RitsuLib 路径不适配本机多程序集安装，首次编译失败；仅在被忽略的本地检查配置中导入已安装的 0.111.0 引用表后完成验证。输入/生成目录隔离于 `.local/mp-coverage/`，日志 `.local/mp-coverage-configured.log`。该静态目录检查不扩大多人运行时验证范围。

未验证：真实主机/客户端连接、网络操作交错、断线重连、可见 UI 布局、三/四人原生全量对照及所有角色/遗物/第三方 Mod 的组合。离线合同是局部语义证据，不替代游戏内联机验收，不宣称 FPS 或实机提速。
