# 多人军师（基于官方 0.50.1 后续主线）

当前代码基于官方 **0.50.1 后续主线**（`5c773caa`），fork **0.50.2 发布准备**。当前交付状态统一见[版本索引](releases/README.md)，本轮证据见[合并记录](archive/strategy/upstream-0501-merge-20261009.md)。多人继续使用本机贡献目标、无来源伤害折算与手动重算，支持烘焙手套原生选牌期间计算。

多人使用三敌方周期的本机贡献目标、伤害/代价前沿与最长十四周期的条件续行。无来源实际伤害按阶段人数折算参与选路，个人贡献仍按真实归属。阶段目标的[实施依据](archive/strategy/multiplayer-cooperative-planning-20260922/implementation.md)与[伤害归属实验](archive/strategy/multiplayer-shared-damage-20260923/implementation.md)保留原始版本和结论范围。

[原生实验](archive/strategy/multiplayer-experiments-20260923/implementation.md)包含完整牌组、独立队友、交错行动、连续手动请求和团队终局。前提始终是只有本机使用军师，队友按自己的判断行动，无需服从或等待建议。受控实验已出现收益与恶化个案，真实联机表现和可见性能仍未验收。

## 使用方式

- 主机或客户端均以本机玩家为决策者，不假定玩家列表第一位就是自己。
- 按「重新计算」捕获当时的整个战场。烘焙手套要求从手牌耗尽一张牌时，也可先计算推荐选择及后续路线，再自行选牌确认。其他回合开始选择仍需先完成；队友尚在选择时需要等待。只有手动按钮发起重算，新回合、自己或队友的操作不会自动重算。
- 烘焙手套选牌页在计算和停止计算时保持可操作；计算期间自行确认选牌，或队友改变战场，旧建议会标记「战场已变化」。再次手动计算使用最新全队状态，不替任何人选牌。此暂停点目前只支持原版回合开始效果，第三方回合开始扩展会明确报告暂不支持。
- 尚有动作/选牌在结算时显示等待提示，完成后继续这次手动请求；启动失败会显示原因。更新 Mod 后重启游戏以加载新版本。
- 多人面板隐藏执行、全自动、自动计算和采纳入口；停止按钮保留当前候选，尚无新候选时保留上次完成的建议。后台只模拟，不替任何玩家出牌、用药、结束回合或选牌。
- 队友行动后旧建议仍保留，显示「战场已变化」。再次按重新计算会取消并等待旧搜索退出，再捕获稳定的新局面。结束战斗会清理搜索和建议。
- 队友死亡后，等待死亡结算完成仍可手动重算。完整保存死亡队友的残留能力和物品，按游戏的停用状态排除其效果；复活后恢复生效。死亡时保留能力不再导致根捕获失败，死亡队友也不再产生佩尔之眼额外回合。证据与限制见[死亡队友验证](archive/testing/multiplayer-through-0481.md#0436fork死亡队友重算2026-09-21)。
- 药水加入每个合法动作节点的搜索，包含使用时机、玩家/敌方目标和本人的选牌；保护及强制用药设置继续生效。多人不套用单人额外的省血门槛审计，也不借用单人已找到的胜利路线来裁剪候选。
- 多人不采用单人的局外成长额度；疯狂科学的改进效果正常归属于持有者，但不因此扩大多人战损目标。读取整场历史的牌继续按原效果的玩家范围统计，单人的增量计数优化不借用任何队友身份。
- “至少用一瓶”只认可原战斗追踪窗口内本机的已用药记录；队友用药或给本机投药不解除本机要求。本机先前已用药时继续沿用原规则，不要求每次手动重算再喝一瓶。
- 遗物提示标注「自己」或「队友编号」。结束回合建议也会列出随后结算的队友被动；例如「队友 1：佩尔之眼：额外回合」只表示队友获得额外回合，不表示本机可以再出牌。不同玩家的同名遗物分别显示。

## 推演假设与取舍

搜索默认最多覆盖十四次敌方行动周期；额外玩家回合不消耗这个窗口。普通多人请求的时间和节点上限均为性能设置值的两倍，例如默认中档从 120 秒 / 120,000 节点变为最多 240 秒 / 240,000 节点；这是停止上限，不要求每次等满。Beam 宽度、并行度和内存配置不增加，单人设置不被改写。显式固定测试预算或时间覆盖保持原值，不再乘倍数。搜索按当前前沿尚未完成的敌方周期分摊剩余预算，额外玩家回合不算已完成周期；原单层最低额度和全局停止条件继续生效。

面板区分返回路线深度、实际搜索曾到达的周期、十四周期上限与本次比较周期，详情显示有效预算。预算不足时可以提前返回，未完成首周期明确提示缺少受击评估。搜索到更深的条件世界线不表示返回路线具备该深度的安全保证。

### 本机阶段目标

首次手动请求冻结当前存活玩家集合，以剩余有效敌人生命向上均分作为本机目标，期限为接下来的三个敌方周期。敌人生命保持原值，达到个人目标也照常反击；不要求本机独力清场。治疗、同回合重算及额外玩家回合不延后截止。人数因死亡/复活变化时按新根重建任务，保留原截止和上一阶段结果；截止已过则新建三周期阶段。阶段账本只在本场战斗内保存，重新加载 Mod 不恢复它。

有效进展从阶段起点计算：仅计真实归属于本机或本机召唤物的扣血，不计过杀；队友或归属未知的扣血不支付本机目标。敌方治疗、复活和新增生命可能冲回进展。已经存在的被动效果照常结算，真清场优先于个人份额。

中毒等效果可能在游戏历史中没有明确伤害来源。选路时将这类实际扣血按本阶段参与人数折算，兼顾持续效果与防御；明确属于队友的伤害不会混入。折算值单独显示，不改变本机的已付/预计贡献或达标提示。治疗和重复重算不会重复取得信用，人数变化按新阶段重建。原生伤害与毒层数照常结算，具体公式与验证见[伤害归属实验](archive/strategy/multiplayer-shared-damage-20260923/implementation.md)。

目标是软约束：综合已经结算的生命/最大生命损失、药水代价、救命消耗、队友存活及目标缺口。接近目标时，最后一点非击杀伤害不会自动压过大量战损；没有达标见证显示“尚未证实”，不声称不可达。具体公式和未校准参数只在[技术记录](archive/strategy/multiplayer-cooperative-planning-20260922/implementation.md)维护。

### 未击杀时如何选择长线方案

一次搜索在原预算内保留有界伤害/代价前沿，包括低战损、高进展及达标代表。用药资格先过滤，整批冻结比较周期，再压缩至最多四倍 Beam；中间保路仍覆盖防御、进攻、能力铺垫。比较周期是当前池已完成的最深周期，但不超过阶段截止。缺少该周期证据的路线保持未知，不拿没算出的来伤当零。

确定的近期死亡先避开；阶段内存活后比较实际成本。阶段之后只有本机主动行动的续行，作为带折价的条件收益与风险：已实现伤害能支持长线铺垫，后续死亡有代价，但不作为“本机必须单独撑完十四周期”的绝对否决。展示保留所选阶段动作，后续条件参考不追加为行动承诺。终局发生在比较边界以内时读取真实终局事实，不能被旧检查点遮住。

前沿不是完整枚举，不保证全局最大伤害或每局正收益。长线检查保留了晚回本收益，也保留更晚回本未被选中的反例。纯团队辅助依赖队友后续主动消费的价值仍未知，不按易伤名义层数虚构队友输出；即时治疗、格挡及本机自己消费的易伤仍按真实模拟参与评价。

所有玩家各自的手牌上限、血量、格挡、资源、牌堆、药水、能力、遗物、球、怪物状态及 RNG 从当前战场冻结。未来假设队友不再主动出牌/用药，但照常处理其回合阶段、被动效果、抽牌和受击。因此这是一条有条件的建议，不是队友未来行为的预测，也不把未知的队友输出算作已造成伤害。

佩尔之眼按各自持有者结算：未参加队友额外回合不算作自己空过回合；自己的其他效果给予额外回合时，也按游戏规则消耗自己的佩尔之眼。仅队友参加的额外回合由模拟自动跨过，本机动作仍等到自己的可操作回合。

需要队友选择时明确停止在「等待队友选择」边界，包括向队友投掷需要选牌的药水；不替队友决定。未支持效果形成明确边界。玩家列表中的目标带编号，重复职业也能区分。

## 复用与单人隔离

每次搜索继续使用现有分支 Fork、完整状态去重、转置表、选牌前缀、并行展开和预算控制。多人状态键补充所有队友的可变状态；只描述单人效果的动作支配/小型 Pareto 不能据此淘汰多人分支。

多人保路在既有 Beam 内先覆盖防御、进攻和铺垫代表，再补剩余名额；不另外开树或追加预算。原始周期观察使用至多十四条不可变短链，本机/总伤害/无来源伤害计数随 Fork 复制。同一战斗状态而伤害归属或比较检查点不同的路线由去重和转置标签区分；这些政策历史不进入战斗状态键或原生对账戳。前沿支配同时检查实际多人评分，避免个人贡献坐标误删持续伤害方案。跨请求仅 Runtime 保存已观察的阶段任务，不保存预测分数。

跨次最多保留四条路线的纯动作数据，每条最多重放当前回合的 32 个无选择动作。旧动作在新根上重新检查牌实例、费用、目标、药水指令并重新模拟，之后作为候选起点；不保留旧树、旧分数、旧影子对象，也不强制采用旧路线。非法首步不复用，遇到选择或回合结束便停止前缀复用。复用工作计入当前请求节点及转移统计。

这能让已找到的合法动作组合较早参加比较，但没有证明总耗时一定下降；这里不报告提速倍数。本人已经执行旧路线前缀时暂不自动匹配剩余后缀，也没有跨不同状态直接返回缓存结果。

多人策略由 `MultiplayerSearchPolicy` 注入，Runtime 不修改持久化的单人自动计算设置。多人绕开单人磁盘路线恢复、反事实用药审计、局外收益目标和自动部署。既有单人分支与比较器保持原路径。

上游更新合并后仍可能影响多人：战斗模拟、候选展开、去重和并行调度共用；多人评分和铺垫通道也消费公共的持续增益、可用手牌与铺垫估值。搜索预设的 Beam、分支数等参数继续沿用，普通时间/节点额度在其基础上乘二。改变这些公共输入，即使没有修改多人专属文件，也可能改变多人探索范围和建议。三周期贡献目标、最终伤害/代价前沿及十四周期边界由多人对象维护；单人能力承诺、组合追加搜索与无治疗证书另有显式隔离。上游发布本身不改变已安装 Mod，影响来自后续合并、构建和安装；合并应按实际调用链选择多人验证，不能只凭文件名判断。

官方 0.47.1 的开局后验、前两回合深入探索和本地开发策略脚本只进入单人搜索；多人明确关闭对应深度、预算和脚本。公共混沌药水结算保留「原药水计成本、补槽生成药水免费」的分支来源，按玩家／槽位随 Fork 保存，消费或替换清除；多人阶段代价直接使用实际累计成本。墨刃附魔的卡牌来源与油灯联动属于共享语义，因此同时进入多人预测。

官方0.48.0的剩余治疗证书、已知回血来源判断与智能药水资格剪枝均只用于单人。多人根不计算这些资格，仍以完整缺血余量和个人贡献前沿选路；回合末临时属性、充能球、费用持续时间与召唤目标则属于共享语义并沿用官方修正。本轮证据见[合并记录](archive/strategy/upstream-0480-merge-20261002.md)。

官方0.47.2新增的请求账本、固定前缀计划发现和跨回合承诺仍归单人；多人solver清空单人计划承诺，首动作目标检查迁到共享候选入口后继续使用冻结状态。2026-09-28的九类原生场景、31／32项多人合同和四对官方单人对照通过；范围与GC未验证边界见[历史合并](archive/strategy/upstream-0472-merge-20260928.md)。

2026-09-27 合并回归覆盖原生烘焙手套选牌／控制、单人同进程恢复、29 项兼容合同与 32 项贡献合同；两根单人对照与官方 0.47.1 的 168 项非时序字段一致。范围和失败记录见[历史合并记录](archive/strategy/upstream-0471-merge-20260927.md)，不作为真实联机质量或可见性能证明。

金币和最大生命回复沿用官方结算；多人金币回调按分支中的持有者活动状态派发，队友死亡不再中断其他玩家的金币收益，复活后恢复其回调。金纸消费每件遗物自身的延迟耗尽次数，额外回合只结算参与者，不另建多人重复计数。卡牌与药水效果嵌套沿用同一引擎作用域，队友需要选牌时仍形成明确边界。
