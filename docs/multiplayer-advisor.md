# 多人军师（基于官方 0.41.0）

本 fork 从 `0.40.3` 起提供多人建议模式；`0.40.4` 修复首次手动计算被旧单人记录限制阻断的问题；`0.40.5` 改为在单回合 3 HP 扣血目标内优先输出。已发布版为 [0.41.2（fork）](releases/0.41.2-RELEASE_NOTES.md)，基于官方 `0.41.0`，包含此前保路配额、共同周期比较和有效救援优化，以及 `b29d6fc` 的资格过滤和同次选路共同周期修正。当前任务分支另含[第二轮复审首批修正](strategy/pro-review-0412-20260918/implementation.md)，尚未发布；本文描述该分支行为。单人继续使用官方 `0.41.0` 的搜索政策和自动执行入口。官方 `v0.41.0` 标签不包含 fork 优化，`v0.41.2` 也不包含本次开发改动。原始研究与历史版本由[策略索引](strategy/README.md#多人研究归档)归档。多人功能尚未完成真实联机验收。[长线收益诊断](strategy/pro-long-term-20260918/README.md)已归档；它不改变默认多人策略或单人路径。

## 使用方式

- 主机或客户端均以本机玩家为决策者，不假定玩家列表第一位就是自己。
- 发牌和回合开始选择完成后，按「重新计算」捕获当时的整个战场。只有这个按钮发起重算；新回合、自己或队友的操作不会自动重算。
- 尚有动作/选牌在结算时显示等待提示，完成后继续这次手动请求；启动失败会显示原因。`0.40.3` 出现点击完全没有反馈时，升级到 `0.40.4` 并重启游戏。
- 多人面板隐藏执行、全自动、自动计算和采纳入口；停止按钮保留当前候选，尚无新候选时保留上次完成的建议。后台只模拟，不替任何玩家出牌、用药、结束回合或选牌。
- 队友行动后旧建议仍保留，显示「战场已变化」。再次按重新计算会取消并等待旧搜索退出，再捕获稳定的新局面。结束战斗会清理搜索和建议。
- 药水加入每个合法动作节点的搜索，包含使用时机、玩家/敌方目标和本人的选牌；保护及强制用药设置继续生效。多人不套用单人额外的省血门槛审计。
- “至少用一瓶”只认可原战斗追踪窗口内本机的已用药记录；队友用药或给本机投药不解除本机要求。本机先前已用药时继续沿用原规则，不要求每次手动重算再喝一瓶。

## 推演假设与取舍

搜索默认最多覆盖七次敌方行动周期；额外玩家回合不消耗这个窗口。节点/时间预算不因窗口扩大而增加，预算不足时可以提前返回。面板分别显示路线实际推演深度、上限与选路的共同周期边界，不保证每次达到七回合。首个敌方周期尚未完成时明确提示缺少完整受击评估。Beam 是有界启发式搜索，不承诺全局最优。

[2026-09-19 窗口研究](strategy/pro-horizon-20260919/README.md)比较了 3/5/7/9 周期和自适应候选，决定保留默认七周期：缩短会遗漏延迟收益，加深也可能为队友提前结束的战斗做无效铺垫；自适应提示及额外扫描尚无足够优势。这个决定不表示七最优，也不代表队友未来一定按预测行动。共同周期字段在全终局候选池中可能取上限作哨兵，实际完成深度应看路线自身。

按用户确认的多人打法，每个敌方周期以本机扣血不超过 3 HP 为目标，优先避免本人死亡，再比较救命资源消耗和超额扣血；同等风险下优先真实胜利和保住队友，再压低敌人剩余生命。当前救命资源按全队次数汇总，尚不能独立比较本机与队友的消费，且该次数排在本机超额之前；这是[本轮复审确认的口径限制](strategy/pro-review-20260918/local-review.md#r3全队资源观察与本机风险)，调整优先级尚未实施。输出相同时少扣血，相同收益时少用药。没有满足额度的路线时仍会给出超额较少的建议。路线比较使用已经完成的共同周期，搜索更深本身不加分；具体续行后来出现的死亡、复活消耗、超额或队友死亡仍作为反证，不能藏回较早的安全检查点。

3 HP 按每个敌方周期分别计算，不是七回合共用的 21 HP。使用本机实际未格挡扣血，包含自损以及手动计算前本轮已经支付的部分；治疗不抵扣已用额度，重新计算和额外玩家回合也不刷新。下一玩家回合开始的自损属于新的周期。面板会显示扣血目标与当前预测中最高的单周期扣血，供玩家决定是否采用。

所有玩家的血量、格挡、资源、牌堆、药水、能力、遗物、球、怪物状态及 RNG 从当前战场冻结。未来假设队友不再主动出牌/用药，但照常处理其回合阶段、被动效果、抽牌和受击。因此这是一条有条件的建议，不是队友未来行为的预测，也不把未知的队友输出算作已造成伤害。

需要队友选择时明确停止在「等待队友选择」边界，包括向队友投掷需要选牌的药水；不替队友决定。未支持效果形成明确边界。玩家列表中的目标带编号，重复职业也能区分。

## 复用与单人隔离

每次搜索继续使用现有分支 Fork、完整状态去重、转置表、选牌前缀、并行展开和预算控制。多人状态键补充所有队友的可变状态；只描述单人效果的动作支配/小型 Pareto 不能据此淘汰多人分支。

多人保路在既有 Beam 内先覆盖防御、进攻和铺垫代表，再补剩余名额；没有扩大搜索预算。单周期扣血账本归属搜索节点，原始周期观察使用至多七条不可变短链。同一战斗状态但已用额度、此前超额或比较检查点不同的路线由去重和转置标签区分；这些政策历史不进入战斗状态键或原生对账戳。

跨次最多保留四条路线的纯动作数据，每条最多重放当前回合的 32 个无选择动作。旧动作在新根上重新检查牌实例、费用、目标、药水指令并重新模拟，之后作为候选起点；不保留旧树、旧分数、旧影子对象，也不强制采用旧路线。非法首步不复用，遇到选择或回合结束便停止前缀复用。复用工作计入当前请求节点及转移统计。

这能让已找到的合法动作组合较早参加比较，但没有证明总耗时一定下降；这里不报告提速倍数。本人已经执行旧路线前缀时暂不自动匹配剩余后缀，也没有跨不同状态直接返回缓存结果。

多人策略由 `MultiplayerSearchPolicy` 注入，Runtime 不修改持久化的单人自动计算设置。多人绕开单人磁盘路线恢复、反事实用药审计、局外收益目标和自动部署。既有单人分支与比较器保持原路径。

## 首批策略优化（已实施）

2026-09-17 根据用户提供的[策略研究原文](CombatSolver_Multiplayer_Strategy_Research_and_Design.md)，从兼容合并 `7160d2f` 实施三步改进。原研究基线 `f220a6b / 0.40.5` 保留历史语境；本批单人对照为官方 `0e6cc2d / 0.41.0`。继续复用 Beam、合法动作展开、全队模拟和请求预算，新增一个多人评估分片与一个纯值记录，没有第二套 Planner、残值接口、长期树或策略版本开关。

### 保路配额

先取得防御、进攻、铺垫各自的代表。同一候选覆盖多个类别时不再为重合类别强取第二名；覆盖代表后才轮流补充，最后按原多人总榜填满。

- Beam 至少为 4：保留总榜第一与三类代表；重合不多占位置。
- Beam 为 3：优先三类代表，不额外承诺第四个总榜候选。
- Beam 为 2：保留总榜第一，另一个名额按候选的稳定动作深度轮换，不使用随机数或跨请求状态。
- Beam 为 1：只保留总榜第一。没有合格存活代表时按总榜补位。

配额只保护探索机会，不保证特定首动作一直保留。既有防御通道仍可用格挡作为探索特征；最终结果不因格挡数字大而获奖。

### 共同周期与已知风险

`Expansion` 在敌方周期结算完成、下一玩家准备阶段之前记录周期、本人 HP/累计扣血、复活消耗、有效敌方 HP、存活人数和用药数。不可变记录引用此前周期，Fork 可共享历史；没有额外模拟器或战斗状态副本。账本继续把根已付扣血计入第一周期、把下一开始阶段自损计入新周期。

当前任务分支先从完整发布池筛选满足用药要求的路线，再确定最浅的已完成周期并裁剪候选。预览和最终返回使用同一段多人处理逻辑；一次选路从裁剪到选择、结果深度元数据都使用同一个批次上下文。真实提前胜利/死亡是终局，外部选择和未支持边界不是；无法完成共同周期的路线不与已完整受击评估的路线冒充同等证据。全部候选都被阻断时仍可报告最后观察及其边界。比较器不会为每一对候选临时换深度。

0.41.1 曾在截断后才检查“至少用一瓶/最少显式用药”，并在子集上重建共同周期。[复审与本地核对](strategy/pro-review-20260918/local-review.md)保留原始发现；2026-09-18 按用户指令实施第一批修正，并随后定版为 0.41.2。已终止的候选在中途压缩时也先检查资格；仍能继续展开的未用药前缀不因最终要求被提前排除。没有合格结果时继续明确报告用药条件未满足。资源归属、默认风险顺序与两步挑战不属于这次修正。

预算停止时保留上一回合层的有界候选组，供最后一次共同周期比较。只留已释放模拟器的节点与数值，选中的路线由现有结果物化流程重放，转移仍计入原请求统计。首周期未完成时仅提供带明确提示的未完成建议，不把未来来伤填成零；已返回的短前缀也不代表后续七周期安全。

共同边界内依次考虑逐槽强制药水满足情况、本人实际死亡、证据完整性、全队救命次数、逐周期超额、真实胜利、队友存活、敌人生命、本人扣血/余血和药水。同一路线在更后面已经发生的死亡、救命消耗、超额或队友死亡仍参与风险判断；不能用它较早的安全观察掩盖。这个反证只否定具体续行，不封禁同首动作的其他合法路线。尚未展开的未来仍然未知。

其他事实相同时，未终局路线只比较共同周期结束之前的动作成本；更多的后续动作本身既不加分，也不扣分。实现沿节点父链找到实际跨入该敌方周期的动作，额外玩家回合不会误当成敌方周期。完整终局仍比较完整动作，尚未完成共同周期时保留原估值后备。该修正属于[2026-09-19 窗口研究批次](strategy/pro-horizon-20260919/README.md)，尚未发布。

[第二轮复审首批修正](strategy/pro-review-0412-20260918/implementation.md)已让真实胜利/死亡使用完整终局事实，只有未结束路线才回看共同周期；没有把胜利提到本机死亡、救命资源或已知超额风险之前。多人也不再因池中存在一条本机无损满血胜利而提前停止，仍受原预算和窗口约束，因此可能比旧版使用更多原有搜索额度。根前用药输入按本机归属修正，最终资格过滤本身不重复增设规则。

完成池局部压缩与最后联合比较仍可能使用不同候选集合；末父节点的已付卡牌候选及旧当前回合预览旁路也仍有研究期限制。默认全队救命次数与风险次序保持原样。后续条件、未验证范围和暂缓理由集中见[实施与归档记录](strategy/pro-review-0412-20260918/implementation.md#保留的条件项)；其中共同周期外动作数偏差已由窗口研究批次修正，其他条件项仍暂缓。不能把这些修正理解为所有入口已完备或联机策略已最优。

### 有效防御、救援与铺垫

删除按全部怪物名义攻击总和计算的格挡加分，直接使用已经结算的周期事实。同等本人风险下，保住队友先于多打少量伤害；无效、过量或给错受击对象的格挡没有单独的终局奖励。已有减伤、抵销与攻击目标继续由模拟器真实结算，没有逐动作新增探针或复制单人 StandPat 的假设。

能力与牌流估值仅用于中间保路，最终共同周期不奖励未兑现的铺垫。短窗口适合直接输出，后续周期确实能兑现的能力路线才可能胜出；依赖真人队友主动配合或未知选择的收益不提前计入。保护/强制药水指令、每周期 3 HP、本机手动重算与七周期上限保持既有合同。

### 暂缓的设计

| 研究建议 | 本项目的取舍 |
|---|---|
| 多个生产策略版本与回退模式 | 基线由固定提交和离线对照保存；先不增加玩家设置或维护三套策略。只有出现实际的切换需求才加开关 |
| 主动队友多情景、概率及鲁棒聚合 | 首版保持队友无主动动作的条件模拟；它不是最坏情况保证。先用反例证明被动假设是主要误差，再设计有限情景 |
| MCTS/PUCT、训练价值网络 | 同候选比较和保路问题解决后，若仍有同预算下反复丢失好首动作的证据，再研究更换生成器 |
| 残值 provider、能力注册、独立 LRU 与长期搜索树 | 没有已验证的多个实现或性能瓶颈，不先建扩展框架。跨请求仍只复用经过新根重验的纯动作 |
| 全引擎“仅人眼可见信息”屏障 | 用户要求是无法预知真人队友行动，不等于新增公平信息模式。继续遵守冻结根的现有信息合同；隐藏牌序/RNG 的产品政策另议，不能借策略优化重写公共引擎 |
| 固定 45%/25%/20%/10% 预算切块 | 没有成本数据支持这些比例，先复用现有请求计量与截止条件；只为发现的饥饿或重复工作补最小调度 |
| 单席位两步前缀挑战 | 0.41.2 第二轮研究撤回优先推荐；先修现有事实/资格/交付，只有真实延迟组合失败输入和包含重放的同预算收益成立时再试，不占默认批次 |

### 验收与当前状态

本批用游戏 `0.111.0` 真实托管模型复现并修正：小 Beam 配额饥饿、深两周期空过压过浅一周期攻击、为 6 伤害放弃救援、已有伤害抵销仍奖励名义格挡。短搜还验证了升级能力牌在两周期兑现 27 伤害、四节点预算保留首周期结果、具体续行的致死/超额反证、提前击杀、27 组三候选排序一致性、原始检查点 Fork 隔离与既有九个扣血合同。用牌模型 ID 仅标识 fixture，不代替官方中文名称。

七周期合同通过六次原生完整状态对账；官方单人哨兵 80 项比较一致，包含完整路线、目标、选择、资源与 RNG。详见[本批测试矩阵](TEST_MATRIX.md#多人策略首批实施2026-09-17)与 `MULTIPLAYER-STRATEGY-COMMON-CYCLE` 结构化证据。结果只覆盖这些固定输入，不代表联机胜率、所有角色质量或可见性能改善。

### 0.40.5 单周期扣血目标

`c172621`（0.40.4）基线将 1 HP 损失在中间评分中等同于 1000 点敌人伤害，终局又先最小化整个窗口扣血。`FUZZY_WURM_CRAWLER_WEAK` 的双卡短搜复现：只有 1 点来伤时仍选择防御、打 0 伤害。相同输入在新策略下选择攻击，损失 1 HP、造成 6 伤害。

`--multiplayer-strategy-contracts` 使用游戏 `0.111.0` 的真实托管模型，双玩家、本机索引 1。固定 100 节点、1 秒预算、DOP 1；前八个双卡案例为 Beam 2，第九个四卡案例为 Beam 12。每次搜索等待上限 30 秒，原生步骤上限 20 秒；最终整个合同步骤 0.862 秒。

| 场景 | 期望和实际结果 |
|---|---|
| 仅剩 1 / 2 / 3 HP 来伤，攻击或防御二选一 | 分别损失 1 / 2 / 3 HP，均造成 6 伤害 |
| 同根剩余来伤 4 HP | 防御，损失 0 HP、造成 0 伤害 |
| 来伤 3 HP，本人只剩 3 HP | 防御避死，损失 0 HP |
| 无来伤 | 攻击，造成 6 伤害 |
| 能量允许相同输出下补防御 | 造成 6 伤害、损失 0 HP |
| 敌人只剩 6 HP | 立即击杀，损失 0 HP |
| 本轮已付扣血后治疗并重算，可再次自损换额外攻击 | 采用无额外扣血的 6 伤害路线，不重新消费额度 |

3 HP 案例开启增量/完整重放等价。另以真实回合开始自损区分旧周期和新周期，预测与原生下一回合的完整 `ContinuationStamp` 全文一致；Fork 子分支修改周期末检查点不影响父分支或旧根。账本断言覆盖分散的 3+3 HP 不超额、0+6 HP 不能挪用上一周期额度、同周期两次 2 HP 合计超额 1 HP；主线程历史捕获确认治疗不抹去已付扣血。九个结果均检查摘要投影的额度/最高值。

### 三回合实现阶段

前一任务固定 Beam 12、350 节点、12 秒软预算，单请求最多等待 90 秒，实际各轮均在数秒内结束。两个遭遇 `FUZZY_WURM_CRAWLER_WEAK`、`FOGMOG_NORMAL` 覆盖：

- 两次原生完整回合与预测 `ContinuationStamp` 全文一致，包括双方牌堆、历史、能力、怪物行动、生命、资源和九条 RNG；第三次敌方周期触发窗口边界。
- 实机推进后旧根重放结果不变；实机消耗生成 RNG 后，新根状态不同，旧根仍保持原值。
- `Lift`、`BelieveInYou`、`TagTeam`、`Flanking` 的单动作原生对账，以及向队友使用格挡药水的对账。这里使用模型 ID 标识测试输入，不代替游戏中文译名。
- 额外回合原生对账；FOGMOG 场景暴露并修复了额外回合期间未行动队友的历史计数未失效问题。
- 队友回合开始需要选牌时形成边界；本人同类选牌继续展开，并开启增量/完整重放等价检查。
- 生成卡牌药水对本人展开选项，选中结果与原生用药全文对账；对队友则形成外部选择边界。
- 立即用药击杀、禁止用药、强制用药；有效旧路线重新验证 3 个动作，非法牌实例的旧路线验证数为 0。
- 强制多人 Runtime 条件下，自动计算/执行能力为 false；执行、全自动、接管和自动回合搜索入口均在触碰 UI/真实操作之前返回。
