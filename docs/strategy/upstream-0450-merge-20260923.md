## 来源与范围

本轮按用户“合并兼容 fork 的最新上游、neat-freak 整理归档、发布最新 release”的请求执行。起点为多人分支 `70212bc2640b14e822523b060d7804a07620802f`，上游为 `Torch1230/CombatSolver` 的 `68700c2365e78e8e53aaf577522793f43da6594a / 0.45.0`。一次不取标签的远端更新确定输入，保留官方与 fork 的同号标签各自身份。

fork 版本定为 **0.45.1**；相对最近公开的 fork 0.44.1，包含此前仅本地准备的0.44.2共享伤害策略及本次官方兼容更新。0.44.2历史包不改标、不补发。官方0.44.1与0.45.0玩家日志原文移入 `docs/releases/upstream/`，fork0.44.1日志保留。最终来源提交、ZIP和渠道凭证由[版本目录](../releases/README.md)维护。

本机是唯一使用军师的玩家，队友独立行动；生产搜索不预测队友主动决策。多人仍手动请求与操作、最多十四敌方周期、普通时间/节点额度乘二而固定预算不变。没有新增多人评分因子，也没有把官方单人成长策略接入多人。

## 失败与夹具收窄

1. 首次UI本地化请求误用 `FUZZY_WURM_CRAWLER_WEAK`，原生四怪站位合同在怪物初始条件分支报 `No valid next state found`；先前已完成的语言往返不替代整项结果。改用合同要求的 `PHROG_PARASITE_ELITE` 后通过，没有为错误建局改生产语义。
2. 首次窗口请求完成了控制器/位置/内存合同，但 `stopAfterInitialSetupAssertion` 还会等待初始搜索，最终120秒超时。改用现有 `stopAfterCombatRootSnapshotAssertion` 在前置断言后退出；新请求约25.5秒完成。提交最小夹具[upstream-0450-ui-state.json](../../coverage/unattended/upstream-0450-ui-state.json)，保留首次Failed，不把部分断言改报整项Passed。
3. 失败批次之后只继续未执行项或修改输入后的最小场景；没有重复原生伤害、单人对照或整组64条策略实验。

## 既有实验如何解读

[此前原生闭环试跑](multiplayer-experiments-20260923/implementation.md)的64条/32对、47胜/16败/1超时，以及双胜23对中的3改善/19相同/1恶化均保留为历史结果。它只有4个合成牌组配置、1个模板组和0真人来源；350节点的搜索覆盖、失效建议、复杂选择及真实队友分布仍有限制。这轮合并只证明具名兼容边界，不能补出真人混沌分布、一般正收益或联机胜率结论。本机唯一毒源仍按人数折算的低估也没有解决。
