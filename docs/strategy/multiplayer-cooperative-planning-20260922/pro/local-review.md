# 对 6 Pro 两轮交付的本地审查

这份复核基于已下载的完整首轮交付与配额专项最终补充，区别于本地先行设计。原文不改写；补充结论及最终取舍统一进入[本轮结论](../README.md)。

后续用户明确取消队友行为预测。本页关于最小队友层、主动 actor/choice 和协作反事实的讨论保留为当时的研究审查，不再列为下一步；当前只采用本机配额、共享前沿和本机续行方向。无队友预测不意味着删除已经存在的队友被动效果或要求本机独力清场。

## 可以采用的认识

1. 当前首要问题是多人目标和未来世界模型，而不是单独的搜索长度。现役超额损失优先于实际获胜，源码和本地生产函数探针一致；新增策略应独立定义目标，不能继续靠调大能力牌分数绕过最终比较器。
2. 枚举本机当前牌序、目标、费用、选择仍是核心。少量队友策略与远端续行适合控制分支数量，但不能替代根层枚举。是否更换 Beam/MCTS 必须在相同模型、目标和预算下比较。
3. 队友行动必须合法、按原持有者消费资源、共享外生策略和信息条件。主动行为需要独立 actor/choice 能力；不是给当前引擎随意换 `_player` 或虚构队友 DPS。
4. 应保留长线评价。Q11 反驳了彻底删除尾值后只保近端 HP 的选择；但是按玩家分开的尾值仍有迟发效果盲点，P02 的 0/0 估值与真实第七周期差 40 伤害必须保留。
5. 复杂协作模型必须赚回计算成本。D01 证明它能利用易伤，S10 证明合法时序失配也会让双方生命都更差；R 的相同聚合结果与接近两倍逻辑工作支持先检验便宜新目标。

## 不直接照搬的内容

| 首轮设计内容 | 本地决定与理由 |
|---|---|
| 固定 3 HP 作为软锚 | 用户允许彻底取消，不把旧常量移到加权公式后继续充当默认依据；伤害要求、生存与资源偏好需要单独标定 |
| 1.35/0.65 的血量交换系数、20% 储备、尾值上限等 | 仅是玩具原型的冻结参数，未做风险参数网格或玩家偏好校准；不移植成游戏常量 |
| Beam 8、六代表、三情景、3+2 周期 | 是可运行原型配置，未证明生产最优；尤其不能把 3+2 当成用户要求十四周期输出规划的完整替代 |
| 保留 3 HP 账本及不因治疗减免的主动自损门禁 | 源码历史可以保留作诊断/旧对照；新硬门禁属于未运行的额外政策，会排除可重复治疗或合法牺牲策略，不能悄悄带入默认 |
| 有限死亡罚及当前前缀过滤 | 不足以给“保生存”保证；须把直接事实、条件风险与全队失败分清，规定无安全候选时的返回方式 |
| 默认 D_actor_tail | 首轮结果没有证明其胜过 F_cheap 的一般收益；把新配额/前沿作为第一批主要候选，把复杂协作层作为有条件后续 |

## 配额专项最终补充的取舍

最终补充明确撤回首轮的复杂 D 优先与软 3 HP：共享有界配额见证先做，F0 是新的无 3 HP 便宜回退，H/n 直接输出是强基线，团队净进展才是完整协作方向。本地采纳这个研究顺序，但两种新算法均未运行。原 R 集已被用于选择新方案，后续只能作回归集，需另取未见根。

最终伪代码仍存在严格配额门槛：如果输出 19/战损 0 与输出 20/战损 10 同在前沿，目标 20 会选择后者。报告中间进展曾称 elastic，最终第 5.3、10.3 节却仍只在达标见证中最小化代价。第 5.4 节承认需修改目标政策，尚未提供自动弹性选择规则。保存未达标候选是必要信息保留，不是这个问题的解决证明；默认目标与弹性选择需单独比较。

`K = 3`、团队进展 `0.5H`、储备 `max(6, 0.2 MaxHP)` 和有界表容量都只是未运行配置。前两项可作为测试起点，不能变成新的无依据常量；硬储备及不因治疗减免的主动自损门禁仍可能排除合法治疗循环或必要牺牲。本地不采纳这些数值为默认。十四周期是当前搜索上限，不是默认阶段截止或已被否定的规划长度。

最小队友层先只消费当前剩余回合是合理的限成本候选，但不能先按无队友模型挑前沿，再指望已被删掉的纯支援动作回来。必须保留辅助入口，并对最终竞争者完成同一条件的评价；只给少数候选计算队友收益后与未计算者混排，会把算力差当质量差。

补充将本地探针称为“用户报告”，是因为它只收到这位 agent 转述的结果与源码定位，没有直接运行本地 DLL。本地原始来源在本目录 `local-probes`，不能将这些检查计入外部 6 Pro 的实验数量。

## 证据口径的必要修正

首轮 R 对比的“相同”仅对文中列明的聚合结果成立。R02 在第 3 周期的各敌 HP 为 D 的 `[23,179]`、F 的 `[45,157]`，第 7/14 周期为 `[23,81]` 与 `[45,59]`；总 HP 相同却不是同一威胁状态。两者在该外部协议下均团灭，不代表在别的队友策略下相同。完整提取说明见[原文入口](README.md)。

909 次结果的 `used` 与费用分类账本一致、未超声明额度，但只是内部逻辑单位的自洽。初始化洗牌、Python 容器操作、日志和生产最终重验等没有被逐项等价标定；不能表述为全部物理计算成本均已精确收费。报告记录了真实 Python 耗时，但没有相同生产墙钟截止的对照。

消融围绕初版 D_bundle，而非每项都围绕最终 D_actor_tail。H 与 Q 曾用于改方案，不能继续叫最终独立测试。R 是同一研究者构造的八个锁定后玩具根，有时间顺序上的留出，但不等于独立人员、真实玩家分布或盲测。

外部评估只固定第一手完整当前动作，随后由统一脚本推进；并未每周期重算，因此对滚动配额/阶段期限的质量没有直接证据。本地[期限反例](../local-probes/README.md#重算不断推迟目标的反例)正好补出一个必须单独验证的维度。

首轮没有执行配额算法；不得把 F_cheap 的成绩重命名成配额成绩。配额首选顺序如果改变，是结合用户目标、计算成本与实现依赖做出的工程判断，仍需原生同预算对照。

## 保证应如何表述

完整枚举一个有限、语义正确的已知行动空间，能够得到那个空间与指定目标下的最优见证。生产有限 Beam/时间截断通常只能报告当前已发现候选中的结果；Pareto 也只能保证当前保留集合内不被支配。剪枝若不是为新目标证明安全，连完整候选空间的最优性都不能继承。

已知队友政策、精确模型与相应续行一致性满足时，rollout 文献可给局部改善性质；本游戏的真人策略失配、有限预算和尾值近似不满足自动保证。论文支持算法结构，不能替代真实引擎差分、固定根对照和真人评价。
