## 1. 统一最终建议：改变上一轮主方案，完全撤下 3 HP

### 1.1 明确判定

**首选首版改为 Qε：本机完整当前回合枚举 + 一次搜索的有界伤害/团队进展—代价 Pareto 见证表 + 固定阶段截止的 ε-constraint 选路。复杂的 `D_actor_tail` 队友规划不再是默认优先实现项。**

这个结论包含三个不同层次，不能混称“配额方案”：

|方案含义|本报告的明确判断|
|---|---|
|把“达到明确进展目标后降低战损”与一次搜索共享见证结合|**首选首版架构**。复用枚举与真实引擎，先改目标和保留机制，减少重复搜索。|
|固定要求“本机直接伤害 ≥ 敌方总剩余 HP / 人数”|**必须实现的强基线，不作为完整协作默认硬门槛**。它简单、可解释，但会排除零直接伤害的更好团队动作。|
|缩短敌人 HP，或把配额满足伪装成 `AllEnemiesDead`|**拒绝**。它改变战斗规则并跳过真实反击，不是目标转换。|
|多次重启限时 Beam，用“没搜到”更新二分上界|**拒绝作为首版**。`Unknown` 不是 `Infeasible`，而且重复准备和回放会争抢同一预算。|
|为每个本机方案寻找最配合的队友，或先做完整多情景联合规划|**不优先**。先做同一共享、可见信息、有限范围的队友条件；只有独立对照赚回成本才扩大。|

**新模式完全删除每周期 3 HP：既不作为词典序，不作为软锚，也不作为隐藏探索惩罚、覆盖门禁或 UI 默认承诺。** 保留真实累计扣血、自损、剩余生命、资源消耗等观察。旧 3 HP 仅存在于显式旧模式/历史对照中；把阈值改成 0 并不等于删除，因为那会让每一点扣血都成为“超额”。

低成本回退统一为 **F0：便宜的本机枚举/短续行 + 进展—代价选择 + 有界本机尾值，不包含 3 HP 项，不规划队友主动行动**。这是对上一轮 `F_cheap` 的拟议修改，**不是已经跑过 R 集的那个原样 F**。当配额没有完整见证、队友语义不支持或预算不足时使用 F0，同时显示目标尚未证实；不是无条件回到旧 A。

### 1.2 为什么现在把 Qε 放在复杂队友模型之前

原 `Results.json` 的 `summaries[split="lockbox"]` 已记录：

|R 集 8 个根|原 `D_actor_tail`|原 `F_cheap`|
|---|---:|---:|
|平均搜索逻辑工作|5,998.75|3,124.25|
|外部第 3 周期平均本机 HP|33.125|33.125|
|外部第 7 / 14 周期平均本机 HP|27.375 / 27.375|27.375 / 27.375|
|外部第 3 / 7 / 14 周期平均敌方剩余 HP|134.875 / 24.5 / 13|134.875 / 24.5 / 13|

相同不只是均值：原报告记录两者逐根的外部 3/7/14 周期生命、敌方 HP、累计扣血与药水/救命向量相同；当前回合动作和第 1 周期可以不同。复杂方案多用了约 **92.0% 的逻辑工作**，没有在这些统一外部指标上获益。[R1]

这个结果支持“先减少目标错位和计算税”，不支持以下偷换：

- 不能说 Qε 已经胜过 D 或 F：旧 780 次主对照没有运行 Qε。
- 不能说删掉软 3 HP 后的 F0 已获得上述 R 成绩：原实验目标含有 `0.30 × 超过每周期 3 HP 的部分`。[R2]
- 不能说队友模型普遍无价值：原 D01 易伤先手和 S07 存在收益；S10、D04、R 则限制其默认复杂度。[R1]
- R 对原方案是最后未用于调参的测试集；**在本报告已经据其结果修改设计后，R 对新 Qε 只能作固定回归，不能再次包装成新方案的未见独立测试。**

### 1.3 对旧交付的覆盖关系

本报告替代旧 `Review.md` 第 1、9 节与旧 `Design.md` 第 1、3.3、13 节中的政策优先级：Qε 优先于 D；新模式不保留软 3 HP；F0 代替原样 F 作为设计回退。旧结果、源码记录、负例、合法性边界和未验证声明全部保留，不改写历史 JSON 的算法名或成绩。

## 3. 把“先打够，再降战损”写成正确的问题

### 3.1 决策变量不是一张牌，也不是伪终局

设 `b` 为**本机从当前冻结根到当前本机回合结束的完整合法动作束**，包括牌序、目标、选牌、药水、费用变化以及结束回合。若途中到达需要外部玩家选择的边界，则它只是“待外部选择的前缀”，不能冒充完整动作束。

设 `π` 为所有本机候选共享的续行/队友条件政策，`K_abs` 为当前阶段的固定绝对敌方周期截止。分支的条件进展和代价为：

\[
P_K(b;\pi)=\text{从本次新根到 }K_{abs}\text{ 的条件净任务进展增量},
\]
\[
C_K(b;\pi)=\text{到该边界的实际模拟战损/资源成本}+\text{边界之后的有限剩余威胁估计}.
\]

选择问题是：

\[
\min_b C_K(b;\pi)\quad
\text{s.t. }P_K(b;\pi)\ge D,\quad b\in\mathcal A_{legal},\quad b\in\mathcal A_{risk}.
\]

这里 D 是同一阶段目标扣除已观察进度后的**有符号剩余要求**；实际比较等价于 `已观察进度 + 本次条件净增量 ≥ 阶段目标`，不重复计算根前进展。对于受支持的固定目标集合，团队净增量可写为 `根时任务剩余HP − K时任务剩余HP`，允许因敌人治疗而为负。Q-equal 的直接伤害对照则必须固定“本机归属的非过杀HP损伤”口径；治疗/复活使累计直接伤害与净任务进展分离时，单独标记该基线局限，不把刷伤害当成团队达成。

这就是本项目可采用的 ε-constraint 结构：一个目标优化，其他目标成为约束；它**不要求用 3 HP，也不要求先伪造击杀**。[P1]

`𝒜_risk` 不是“所有想象中的队友坏情景都要无损”。它只包含明确的合法性、资源限制、确定当前致死的处理和公开的生命支出边界；条件世界里的未来死亡另行记录。风险细节见第 5 节。

### 3.2 必须区分四种状态

建议用状态枚举而不是一个容易被误用的布尔值：

```text
NotYetMeasured        没有完整可比结果，可能仍可展开
ConditionalWitness   在声明的模型/条件下，完整到截止并满足配额
ObservedStageMet     真实新根的已观察任务进度已经满足阶段目标
InfeasibilityProof    精确穷尽或有效界证明无解；普通限时 Beam 不产生它
```

还可单列 `ExternalChoice / Unsupported / BudgetStopped` 原因。`NotYetMeasured` 不等于失败，也不等于安全。`ConditionalWitness` 是一个可复放的模型见证，不是“真人一定会配合”。

`ObjectiveSatisfied` 只能是以上状态的查询结果，**不能替代** `AllEnemiesDead`、`PlayerDead`、真实 `CombatEndedTurn`、引擎阶段或本机回合边界。

### 3.3 配额约束不能偷偷吞掉尾值，也不能靠尾值假达标

可分开存：

```text
ObservedProgress        已观察根事实累计得到的任务进度
SimulatedProgress       本次声明条件下，真实引擎结算得到的进度
EstimatedFutureValue    只覆盖模拟截断之后的估值
```

尾值可以帮助探索和 F0 回退、评价剩余威胁，却**不能增加 `SimulatedProgress` 或把未完成 K 的路线标成满足 D 的见证**。如果只有第 1 周期实证加两周期估计，就如实显示“实证 1、估计到 3”，不能拿它与完整到第 3 周期的见证无标记混排。

旧 Q11 表明完全关掉尾值可能重新偏向短期防守，所以不建议“一次前沿”顺便消灭长线估值。但保留有界尾值和把预测伤害当作已兑现达标，是两件事。[R1]

## 4. D、K、人数和分工：默认用团队任务配额，等分直接伤害作强对照

### 4.1 为什么 `H / N` 很值得测，却不足以作协作默认

令 `H` 为阶段开始时敌方真实剩余任务 HP，`N` 为阶段开始时本方参与战斗的真人玩家数。

\[
D_{equal}=H/N
\]

它提供一个清楚的“承担一份输出”的参照，能把“少掉 1 HP 就放弃大量输出”改成“先确保完成任务再优化代价”。对没有主动队友能力的首批原型，它是很有价值的强基线。

但它不能直接等同于最合理的战术责任：全队易伤、救援、虚弱、挡住致死攻击、让输出队友保留费用，都可能由本机承担；队友本来就能杀掉的目标不值得为了抢自己的配额而多花资源。**合作目标不是保证每个人名义上打满相同伤害。** U3 已经给出严格的直接伤害反例。

还要区分时间尺度：`H/N` 是**整场/整阶段总任务的一份**，不是天然的“未来一回合必须打够”。把它塞进 K=1 或任意短 K，会把目标不可达与搜索能力不足混在一起。

### 4.2 Qε 的默认目标定义

**推荐默认查询“团队净任务进展”前沿，不把本机直接伤害设置为所有方案都必须满足的硬约束。** `H/N` 保留为独立 Q-equal 对照、输出解释与可选偏好。这样不是拒绝配额，而是把配额应用在用户真正希望改进的合作任务上。

为使设计可实施，给一个需冻结测试的简单启动参数：

```text
阶段开始：记录真实 H_phase 和绝对敌方周期 c0。
普通阶段：K_abs = c0 + 3；D_team = 0.5 × H_phase。
显示的均分阶段责任：D_share = D_team / N_phase。
对照 Q-equal：在同一截止要求本机直接净输出达到 H_phase / N_phase。
```

**“三周期压掉当前半条团队总血线”是本报告提出的实验起点，不是已有结果导出的最优默认。** 它只有两个明确量：阶段长度与目标进度；不把旧 14 或旧 3 HP 搬成隐藏约束，也不要求在窗口内击杀。下一轮生产冻结对照必须同时保留用户原始 `H/N` 方案，不能只测试修改后的版本。

这两个目标的大小和归属不同，应标明；不能用 Q-team 胜过 Q-equal 来宣称“某个数值的公平分工理论成立”。目标尚未校准时，报告应展示 `D_requested`、已见证的进展区间及 `Unknown`，而不是悄悄把 D 改成刚好当前路线能达到的值。

**不建议首版自动调十几档 D/K 或建立角色预测框架。** 若全体候选都没有满足目标的见证，继续保留目标及截止，选择第 5.3 节的有损回退；不是强行卖血，也不是宣称数学上无解。

### 4.3 危险敌人、成长和角色

团队总 HP 仍不能完全表达危险小怪。首版处理顺序：

1. 当前确定致死与合法救援进入可执行性/生存处理，而不是要求救援牌也打够伤害。
2. 敌方已模拟的出手、死亡后效果与成长，进入同时间边界的真实成本；不再另发“击杀奖金”。
3. K 之后的剩余威胁只计有限尾部，不能把已经模拟避免的伤害再减一次。
4. 若某机制需要“在已知第 q 个敌方阶段前处理特定敌人”，可建立具名任务 `TargetNeutralizedBy(q)`；它和总 HP 配额不是同一单位，不能把一次击杀硬换成一个任意 HP 常数。

普通阶段先固定 K=3。只有**由当前可见机制确定的紧迫截止**才采用更短的具名任务；未知“未来或许成长很快”不能随意把所有计划都变成最坏情景约束。缺少可靠威胁适配时标记未建模，不捏造精确击杀期限。

无需推断真人“是什么职业就一定打多少”。显式角色偏好将来可表达为 `s_i ≥ 0, Σs_i=1`，展示 `s_i D_team`，但默认 `s_i=1/N` 仅作责任参照，**不作每人的独立硬门槛**。没有用户指定与真实行为数据，不自动拟合角色权重。

### 4.4 人数的具体口径

`N_phase` 是阶段开始时记录的本方真人参与者身份集合大小，不含召唤物。它不等于“当前手牌非空的人数”，也不等于“本回合仍愿意出牌的人数”。默认不因为有人本回合已结束、短暂倒下就即时重分配全部硬配额。

永久离场、阶段变换、复活或新目标出现时可以显式关闭旧任务并创建新任务，但必须记录原因、旧任务完成/未完成情况；不能利用人数变化把未完成进度清零。**多人血量缩放已经存在于真实敌人 HP 中，不能再在引擎里乘除 N。**

### 4.5 首版参数的诚实边界

D/K、生命储备、资源价格都是政策，不是算法定理。Qε 的价值在于把这些政策从战斗规则与搜索过程分离，并由同一批见证回答不同目标，而不是声称某组参数不用实验就正确。上述启动参数没有新增运行结果；真正上线默认必须经过第 11 节的冻结对照。

## 5. 丢掉 3 HP 后，怎样避免无限卖血和另一种龟缩

### 5.1 用有单位的代价，而不是新的无限风险轴

建议成本对象保存分玩家向量，标量只用于固定一次选择：

\[
C_K=\sum_i w_i L_i+\sum_e v_e U_e+\sum_i\phi_i(HP_i(K))+T_{threat}(s_K).
\]

- `L_i`：同边界累计实际模拟扣血，包含本机自损；根前已付部分作为常数/预算事实保留。治疗不倒扣已经发生的损失以制造循环奖励。
- `U_e`：按事件 ID、资源拥有者去重的实际消耗；自动仙女瓶不同时按显式用药和救命库存重复收费。
- `φ_i`：剩余生命不足的递增代价，不是“超过 3 就有巨大跳变”。治疗可改善真实生命储备，但不是无限正奖励。
- `T_threat`：仅 K 之后尚未计入 `L_i` 的有限威胁。若使用付费续行直接计入未来损失，就不再给那一段同样的威胁罚。

为减少同时调参，首批可沿用原 F 的其他公开权重作为暂定值，**明确删掉所有超 3 HP 项**；不是宣称原 F 的结果因此仍成立。是否本机 HP 比队友 HP 更贵，是显式产品偏好，不从玩家身份自动得出。

### 5.2 生命支出边界不是“所有条件未来都不得掉血”

在首版中，至少区分：

- 本机动作在外界无法介入之前造成不可恢复的确定死亡：有合法非致死替代时不推荐。
- 本机可控血费：用当前真实生命与明确储备给出有界可支出空间，计入阶段已观察自损；同阶段重算不刷新。
- 队友可能救援也可能不救援：属于条件风险，不当作已获救，也不当作所有世界必死。
- 未来敌方伤害：保留条件结果与不足之处，不能把整个阶段所有最坏条件的损失硬相加成预算。

可测试的初始储备仍可采用原设计的 `max(6, 0.2×真实 MaxHP)`，但它与“每周期 3 HP”没有关联，亦不是已校准最佳值。储备不是实际胜利后的额外禁令：确定战斗结束与仍要受击的状态应分别处理。不能为了达到 D 自动允许本机无界自损、消耗受保护药水，或把队友牺牲悄悄折算成廉价伤害。

### 5.3 没有达标见证时，不能变成“最大伤害不计代价”

令 `W` 为当前已经完成同一比较边界的见证集合。

```text
F_D = {w∈W : legal(w) && allowed_risk(w) && P(w) ≥ D_remaining}
若 F_D 非空：按固定成本 C 最小选；成本相同再选更大进展。
若 F_D 为空：目标状态为 Unknown；从 W 选 F0 的有界进展−代价方案。
若 W 也为空：只返回已验证的可执行前缀并标边界，或明确没有建议。
```

F0 不是“先把 D 降到当前最高值，再把它称为达标”。它在未证实目标时使用透明的有限权衡，保留当前生存与长线进展两端；尾值单独标注。无可比完整层时也不把未知尾部填成零风险。

### 5.4 配额仍有最强的政策反例

**直接推导、未运行：** 同一 K、同样存活与资源，方案 A 进展 19 / 成本 0，方案 B 进展 20 / 成本 10，D=20，且两者都未触及生命支出边界。严格 ε-constraint 必选 B。若额外 1 点进展不触发击杀、减伤、下一阶段优势，这个目标可能让用户付出不合理的 10 点代价。

这不是 Pareto 算错，也不能靠二分解决：A、B 本就互不支配，问题是目标偏好。**因此本报告推荐有界前沿，而不是只保留一个达标解；需要同时报告“目标代价跃迁”与最近未达标替代。** 首版不隐藏地改用加权和覆盖用户目标。若这类断崖在冻结生产集中反复造成外部严格退化，应改阶段目标政策或采用 F0，而不是继续调队友模型来遮掩。

## 6. 精确单调性、Unknown 与“一遍搜，多份配额见证”

### 6.1 哪个命题单调

固定根、完整任务定义、截止 K、合法策略集合、资源/战损条件与队友信息政策，定义：

\[
\mathcal F(D)=\{b:P_K(b)\ge D,\ C/\text{风险满足给定限制}\}.
\]

若 `D2 ≥ D1`，则 `F(D2) ⊆ F(D1)`。所以 D2 有精确可行解，D1 也有；D1 经精确证明不可行，D2 也不可行。这是集合包含的推导，不依赖 Beam。

但限时 Beam 可能因为 D 改变探索顺序，在 D=20 找到路线、在 D=10 反而没找到。**后者只是搜索没找到，不能否定前者携带的较低配额见证。** 换 K、换成本上限、换队友政策或换根之后，原单调性结论的固定问题前提也改变了。

### 6.2 为什么不建议重启二分

一次带预算的搜索已经付出了根准备、状态转移、选牌、队友结算和回放成本。每个得到 `(P,C)` 的合法完整结果天然为所有 `D ≤ P` 提供同条件可行见证。与其对十个阈值开十次 solver，不如维护见证表，然后在**表上**查询。

同表查询只说明同一经验候选集上的不同配额会选什么，不代表每个配额都已独立搜到最优。若探索/保留本身受某个 D 引导，也必须在结果中记录这种偏向；共享见证不是覆盖完整性的证明。

在排序后的见证进展数组上二分查找可以使用；这只是数据结构查询，不是二分重启战斗搜索。若有真正可证的上下界，也可共享分支信息，但首版没有必要假装现有启发式分就是这样的界。

### 6.3 有界经验 Pareto 前沿，而不是精确全局前沿

对同一根、同一绝对边界、同一条件集合和完整证据级别的终端评价项，若 `P_a ≥ P_b`、所有用于选择的成本/风险维度都不差，且至少一项严格更优，可在**已收集结果中**删除 b。

必须保留的重要限制：

1. 中间状态不能只按伤害/扣血两数做安全支配。手牌、敌方阶段、力量、易伤、延迟资源、目标、选择、RNG 与行动者状态不同，未来可达动作就不同。现役多人 `Dominates` 已拒绝跨不同完整状态键直接套用单人摘要支配。[S7]
2. 有界表裁掉了非支配点，就不再是完整 Pareto 前沿；可能丢失某个 D 的唯一最优见证。可称“经验前沿/有界见证集”，不能称精确解集。
3. 第 1 周期的 `(伤害,代价)` 与第 3 周期的同名字段不能直接支配比较。已知坏续行只反驳该续行，不封禁同一当前回合的全部其他后缀。
4. 同一状态但不同已付血费、进度任务、剩余期限、强制药水、可见信息或条件身份，也不一定可合并。

数学上，多目标动态规划的解集可以指数增长或无穷；有限精度/有界表示是有意的近似，不是免费的全保留。[P2]

### 6.4 最小保留设计

不增加现役 Beam 宽度。最终见证表沿用现有 `4×BeamWidth` 的数量级上限，但**这是拟议资源上限，不保证相同实际内存**。条目保存紧凑事实与纯动作路径，模拟器按原所有权释放，最终复放仍计费。

建议原有席位中优先保留：最低代价端、最大进展端、最接近固定目标的达标/未达标见证、已经出现的合法救援/控制/延迟收益代表。它们共享原容量，不各领一组新增席位。满表后用确定性分桶淘汰，并记录被淘汰的当前回合身份；F10 说明任何保路都可能挤掉更好组合，不能许诺不退化。

上面是启发式保留，不是已证明的 ε-近似界。第一批可以仅维护纯标量 `(P,C)` 前沿，另保留必要风险/资源事实；不要先建十几维通用优化框架。若尾值或队友生存会改变最终排序，不能在前沿过滤时把这些维度完全丢掉。

### 6.5 “最大阈值”在没有 K / 战损条件时会退化成什么

- 若伤害是对固定敌人净 HP 的减少、没有额外目标变化，最高阈值通常只是 **H，即重新要求清场**；高血量搜不到击杀的问题回来了。
- 若允许无限时间但限定生存，它变成某种“能否最终清场”的可达性问题，而不是当前回合在有限预算下怎么打。
- 若伤害是累计受击事件，敌人治疗、复活、召唤或重复循环可让它膨胀，甚至无界，鼓励刷伤害。
- 若没有生命/资源限制，则可把本机与队友生命库存都换成伤害，得到不符合“保战损”的解。
- 若只取限时搜索看到的最大值，则它是**当前样本最大见证**，不是最大可行阈值，更不是最适合用户的目标。

所以目标必须带任务口径、截止和代价语义；“自动二分出最大 D”不能代替这些设计。

## 7. 保留真实 HP：单人能力可以复用到哪里，不能套用到哪里

### 7.1 用户给出的“缩 HP”反例必须成为语义红线

U2 的条件：本机 6 HP，敌人真实 20 HP、来伤 8；两能量，攻击造成 10，防御给 5 格挡，目标 D=10。

- 真实攻击 + 防御：敌方剩 10；本机承受 `8−5=3`，剩 **3 HP**，目标达成且存活。
- 真实只攻击：目标数值已达 10，但本机承受 8，**死亡**。
- 把敌方 HP 缩为 10：只攻击会使模型宣告胜利，不执行本来存在的反击，产生“无损”的伪解。

真实团队胜利可以作为 `TaskResolvedByVictory` 完成全局战斗任务；即使本机没有打满个人责任参照，也不应被当作团队任务失败。但直接伤害统计仍保持原值，不能把队友的伤害转记给本机。反过来，个人/阶段配额满足绝不产生胜利。

这同时反对两个错误：缩 HP，以及一旦累计打够 D 就不再补防/结束本机回合/验证来伤。它不是通过一个不同的敌人状态等价求解原问题。有限阶段目标也不等于所有候选都要立即清场：低成本未终局路线可能被选中，但剩余威胁与阶段期限不能被清零；是否愿意为真实即刻胜利额外付费，是明确的代价偏好，而不是又用 3 HP 决定。

还要防止达标标记永久锁存：如果指标是**K 时点净 HP 减少**，中途达到 D 后敌人治疗，K 时点可能重新不达标。`ReachedThresholdOnce` 不等于 `ObjectiveSatisfiedAtDeadline`。沿时间的进展不一定单调；第 6.1 节关于 D 的集合单调性与此不冲突。

## 8. 易伤、救援、团队防御：团队结果为主，反事实贡献只使用一次

### 8.1 默认在结果层补足，而不是把增益层数换成伤害

Q-team 的进展来自真实条件结算后的团队任务状态，成本来自分玩家实际结果：

- 易伤/力量/能量：只有合法消费者实际使用时，才通过敌方 HP 与费用变化进入条件进展。
- 救援：当前保命进入生存事实；被救队友后续合法行动产生的输出进入团队进展，而不是再加一次“救援等价伤害”。
- 团队防御/虚弱：进入实际少扣的 HP 与存活，不再奖励名义格挡。
- 控制/减员：改变敌方实际行动与剩余威胁；不要同时累计总伤害、击杀奖金和已经实现的减伤奖励。

U3 的例子：一能量时，本机攻击 8，队友随后两次攻击 10，团队输出 **28**；本机先给 1.5 倍易伤，队友输出 **30**。直接配额可能淘汰本机伤害为 0 的后一方案。队友已经结束时，攻击 **8** 又优于易伤 **0**。这正是“消费者、合法时序、目标”应进入条件，而不是给所有易伤固定加分的原因。

第一批若仍使用当前不主动规划队友的条件世界，**它不会凭空解决这个例子**。它能先解决旧目标压制卖血与枚举见证丢失；第二批的最小共享队友条件才补当前回合的主动消费。

### 8.2 反事实贡献的正确写法

固定根、K、队友条件政策 `π`、信息权限、随机源和一个合法本机基准动作束 `b0`。`b0` 可以是合法结束当前回合或固定防守基准，必须对所有候选相同；不能为每条候选另找一个更差的基准。

\[
\Delta P(b)=P_K(b;\pi)-P_K(b_0;\pi),
\]
\[
\Delta U(b)=U_K(b;\pi)-U_K(b_0;\pi).
\]

在 U3 的无溢出简单条件中，基准本机不攻击、队友输出 20，因此攻击的增量是 **8**，易伤的增量是 **10**。这是本次基于用户给定数字的直接计算，不是新增模拟。

**默认优先用绝对团队结果排名，把 Δ 用于解释或明确的“边际贡献配额”实验，不同时相加。** 同一固定基准下，最大化 `U(b)−U(b0)` 与最大化 `U(b)` 的次序相同，因此若只是为了排名，根本不必额外模拟基准。这是削减反事实计算成本的重要机会。

错误形式包括：

```text
团队伤害 + 本机直接伤害 + 易伤带来的增伤              // 重复计算
团队效用 + 反事实效用增量                            // 重复计算
已避免的真实扣血 + 同一段未来预计减伤                 // 时间重叠
所有人的边际贡献直接求和，并假定总和等于团队伤害     // 交互作用下不成立
```

当边际贡献真的用于筛选时，基准只为每个根/同条件/同截止付费计算一次；但“队友在候选分支里的合法响应”一般仍须分支结算，不能把根上某一条队友动作轨迹强行复用到所有状态。

反事实信用分配是有依据的方法方向；COMA 使用固定其他行动的反事实基准处理信用分配。但本设计不是其学习算法，也没有学习 critic；顺序回放必须保持合法政策响应，不能机械固定在新状态中已不合法的旧动作。[P3]

### 8.3 队友政策必须共享什么

所有本机候选共用：政策函数、可见信息掩码、行动顺序条件、资源规则和随机源来源。政策可以对不同候选造成的**已经可见的新状态**作同样规则的响应，但不能读取候选 ID、完整本机未来剧本、隐藏牌序或外部评测结果。

不得：每个本机候选都配上该候选专属的最优队友；提前读取后续抽牌决定本机当前第一张牌；看到结果后改变队友类型；给所有条件分别选择互相冲突的当前本机动作再平均。

同种子只是耦合随机源，动作变化可能改变 RNG 消耗次序，所以“同 seed”不保证同事件轨迹。生产必须遵守真实引擎的合法 RNG 过程，不能为了让反事实更好看而随意补齐/删去随机事件。

### 8.4 ready 与 choice 是必须补齐的语义合同

当前 `CombatRootSnapshot` 有 `PlayerCount`、本机身份和阶段等字段，但本次定向检索没有发现独立的原版 `IsPlayerReadyToEndTurn` ready 集合捕获；用户也已指出这个缺口。**本报告不以“手牌尚有攻击、还有能量”推断真人未结束或愿意继续出牌。**

建议捕获明确三态：

```text
ObservedEnded       有受支持的原生已结束事实
ObservedCanAct      原生阶段允许行动；仍不是“真人一定会行动”
Unknown             没有足够可靠的捕获/适配证据
```

`ObservedCanAct` 只能允许建立“会继续行动”的条件，不能保证配合。`Unknown` 不默认为已结束，也不默认免费获得队友行动。第一版缺该适配就回退 F0/只用已发生事实，并显示团队收益未评价。

当前 `RequireLocalChoice` 会在选择属于队友时设置外部边界并抛出专门异常（`SimulatedCombatState.Multiplayer.cs:105–111`）。这是正确的语义保护。需要新增的不是“删掉检查”，而是显式沙箱 actor/choice 合同：

```text
TryApplyActorAction(branch, actorId, visibleLegalAction, actorChoicePolicy)
```

未知选择仍返回明确边界；不能吞异常、把 advisor 身份临时切到队友，或让模拟器发送真实网络操作。当前 `Replay` 从 `_player` 手牌取卡并 `ManualPlay`，不能假装已经是任意玩家 API。[S5]

### 8.5 队友情景的最小成本安排

不恢复原 D 的“三情景 × 多周期”作为首版前提。先对少量前沿附近的完整当前回合候选，使用**一个冻结的、非最优的合法队友规则**补当前回合剩余的行动；后续更远队友行为继续明确为未主动规划的条件，不伪造固定 DPS。

另以“不继续行动/换目标/先后手变化”作敏感性或用户可见依赖，不把所有最坏条件都强行变成硬可行性约束。没有校准概率时，不能称期望胜率，也不能把 1/1 或 3/3 条件达标称为安全概率。

如果一个本机当前回合依赖中途队友插入或外部选择，默认不能当作无条件完整本机束。对交错模型的任何扩展必须保持每个世界共享同一可执行本机前缀；做不到就停在依赖点，等待下一次**手动**请求。这正是原 S10 仍必须保留的反例。

## 9. 固定截止与已观察进度：防止“永远明天再打”

### 9.1 U4 为什么成立

用户给定的三周期排程：攻击造成 10、付 3 HP；防御 0/0；目标 20，先少总损再少近端损。每次都把窗口重新设置成“从现在开始三周期”，会每次计划 **防—攻—攻**，三次执行的却都是防，实际进展 0。

固定阶段绝对截止后，第二次只剩两周期，不能再把两次攻击同时放到新的第三周期之后；在这个完全枚举例子中按 **防—攻—攻** 完成 20。它说明需要跨请求一致的**任务时间**，不是需要跨请求保留预测树。

### 9.2 最小阶段账本

只携带以下不可变、由主线程更新的任务上下文：

```text
PhaseId / CombatIdentity / TaskScopeVersion
StartedAtObservedEnemyCycle
DeadlineEnemyCycle
RequestedTarget 与 MetricKind                       // 公开政策元数据
InitialObservedTargetState                         // 已观察起点
ObservedTargetProgress + ObservationEventCursor    // 真实净进展及去重位置
ObservedOwnBloodSpend / ObservedResourceSpend      // 确有可靠事件时记录
Revision / InvalidationReason
```

任务参数可以跨请求保留；它们是承诺/偏好，不是旧预测分数。**禁止携带**旧节点分、旧 `SimulatedProgress`、旧 `ΔU`、旧队友脚本结果、旧未来伤害、旧 simulator/Fork、旧预测树及旧未来 RNG 状态。

每次手动请求只用当前新根重建预测：

\[
K_{remaining}=K_{abs}-c_{observed},\qquad
D_{remaining}^{signed}=D_{phase}-P_{observed}.
\]

**净进度允许倒退，因此内部不能一律把剩余目标截为零。** 例如阶段已进展 30、目标 20，未来净回退 5 仍满足目标；内部应比较 `30−5≥20`。UI 可以显示 `max(0,D_remaining)` 作为尚欠数量，但判断仍使用总量或有符号差额。

“发生了几次手动重算”和“走了几个本机额外回合”都不减掉敌方周期截止。绝对敌方周期需由真实敌方阶段观察确定，不能直接把玩家回合编号当作等价时钟。

### 9.3 什么进度可以记，什么不能记

推荐默认的团队任务，使用同一目标身份集合与阶段口径下的真实净剩余状态更新。队友已经造成的伤害当然进入团队进度；未发生的预测伤害、配合承诺和模型里的反事实信用一律不记。

**尤其不能把“模型认为本机易伤贡献了 10”写进跨根的事实账本。** 后续真实敌方 HP 变化可以记作团队进度；“其中有多少归本机”仍可能是解释或归因推断，不是同等地位的事实。这也是默认团队任务配额比跨根强制个人反事实配额更容易保持正确性的原因。

若仍测 Q-equal，则需要可靠的本机直接伤害/目标事件归属；归属不明就是 Unknown，不把所有团队 HP 下降算成本机伤害。

敌方治疗可使净进度下降；过杀不额外计入。换形、复活、召唤和阶段转移必须有受支持的任务口径与事件 ID，不能通过重置目标身份刷进度。若没有可靠映射，显式结束旧任务并说明语义变更，不能把它记为已完成。

### 9.4 已达标、截止过期和外界打乱计划

任务定义默认为“截止时点的净任务进展”，不是“历史某一刻碰过阈值”。提前跨线可以显示当前进度达标，但不永久锁定 K 时点见证；真实胜利则使用真实终局事实。阶段到期或真实场景变换时，记录完成/未完成与原因，再基于新观察创建下一任务。

阶段到期没有完成，不得自动把旧目标改名成“新的未来三周期”而不留失败记录。若用户根本没有执行建议或真人改变战场，这不证明算法数学失败，但应记录条件失效；不能继续使用旧分数解释新根。

固定截止本身也会失败：计划可能因队友倒下或目标换阶段变成不可达；继续为了赶旧指标鲁莽卖血也不合理。发生明确任务语义/能力重大变化时允许公开重建任务，但须留存原目标与原因，不能把每次没进展都当成合法重置理由。

### 9.5 尾值的职责

尾值负责表达 K 之后仍存在的能力、资源和成长压力；固定截止负责不把同一配额无限往后挪；事实账本负责辨认真实进展。三者互不替代。任意一个启发式尾值并不自动证明不会拖延，也不能继承 MPC 的递归可行性或稳定性结论。[P4]

本机仍只手动请求与手动执行；新账本可以观察事实，但不触发自动搜索、自动出牌或自动结束回合。没有按建议执行与足够新观察，任何滚动规划都不能保证完成任务。

## 10. 核心伪代码与职责：新目标不伪装为胜利

以下是未编译的设计伪代码，不声称当前已有同名 API。尽量用多人 partial、不可变 records 和纯函数，不新建通用 provider/registry 框架。

### 10.1 类型与所有权

```text
QuotaContext
    RootStamp, PhaseRevision, ObjectiveKind, MetricDefinition
    AbsoluteDeadline, SignedRemainingTarget, ConditionalPolicyId
    InformationMask, ExplicitRiskAndResourcePolicy

QuotaEvidence
    CurrentTurnBundleId, PureLocalActions, CompletedEnemyCycle
    ProgressFacts, CostFactsByOwner, ResourceFactsByEvent
    RealTerminalFacts, BoundaryKind, EvidenceStatus
    OptionalTailEstimate   // 不能用于证明达标

QuotaWitnessTable
    request-local，有界，条目来自同截止/同条件的完整结果
    保留必要不可支配见证和有效 incumbent
    不拥有跨请求 simulator，不把未完成候选填成零

PhaseLedger
    主线程观察事实与任务元数据；worker 只读冻结副本
    发布前校验 RootStamp 与 PhaseRevision；取消的 worker 不回写
```

战斗语义键保持真实战斗含义；`PhaseId / deadline / cost-history / policy / information / scenario` 进入必要的多人搜索标签与缓存上下文。D 作为同一见证表的查询阈值可共享已有结果；如果它改变搜索保留政策，该影响要显式记录。纯显示分不塞进引擎指纹。

### 10.2 一次请求

```text
SolveQuotaAdvice(root, phaseSnapshot, policy, sharedBudget, cancellation):
    assert multiplayer(root)
    context = FreezeQuotaContext(root, phaseSnapshot, policy)
    frontier = ExistingLocalLegalEnumerator(root, originalBeamWidth)
    witnesses = BoundedWitnessTable(originalFinalCapacity)
    completedCurrentTurnFacts = BoundedSameBoundaryFacts()
    incumbent = None

    while sharedBudget.canSpend() and not cancellation.requested:
        node = ExpandOnePaidStep(frontier, sharedBudget)
        if node is None:
            break

        # 保留真实 HP、卡效、死亡与阶段。数值碰到 D 不终止卡效/本机回合。
        facts = ObserveActualBranchState(node)
        RecordLocalCostsAndLegalChoices(facts)

        if facts.requiresExternalChoice or facts.unsupported:
            RecordExplicitBoundary(node)
            continue

        if facts.realVictory or facts.irrecoverableLocalDeath:
            result = CloseRealTerminalFacts(node)
        else:
            # 必须先完成本机当前回合；一般还需要真实模拟反击才能构成阶段证据。
            if not IsCompleteCurrentLocalTurn(node):
                RetainPaidPrefixWithoutOld3HpPenalty(node, frontier)
                continue
            result = TryContinueUnderSharedPolicyToAbsoluteDeadline(
                node, context, sharedBudget, cancellation)

        StoreOnlyActuallyCompletedComparableFacts(result, completedCurrentTurnFacts)

        if CompleteAtRequiredDeadlineOrRealTerminal(result, context):
            # 场景满足是条件见证，不是事实世界已经完成。
            e = BuildQuotaEvidence(result, context)
            witnesses.InsertBounded(e, chargeComparisons=True)

        nextChoice = SelectFromSameContext(
            witnesses, completedCurrentTurnFacts, context, fallback=F0)
        if HasFullyValidatedCurrentTurn(nextChoice):
            incumbent = KeepOwnedReplayableIncumbent(nextChoice)

    DrainAndReleaseUnpublishedBranches()
    if incumbent is None:
        return ExplicitNoCompleteAdviceOrVerifiedBoundaryPrefix()
    return PaidFinalReplayAndPublishIfRootAndPhaseStillCurrent(incumbent)
```

**这里的“RealTerminal”用于完整目标见证时指引擎真正结束的战斗，而不是仅本机死亡。** 本机不可恢复死亡可终止其可执行建议并记录失败，但队友尚存活时，不能把他们后面的战斗假定为吸收状态。具体实现应把 `RealBattleEnded` 与 `LocalAdviceTerminated` 分开。

`TryContinue...` 不能给每条代表重新发一份预算；根枚举、闭合本机回合、条件队友行动、观察、前沿维护、最终复放都从同一账本扣除。必须先保有可执行 incumbent 再花余量；不能到取消时临时拼出“攻击达到目标、剩下大概安全”的半条路线。

### 10.3 查询与 Unknown

```text
SelectFromSameContext(witnesses, completedFacts, ctx, fallback):
    comparable = witnesses.Where(SameDeadlineMetricPolicyAndInformation(ctx))
    eligible = comparable.Where(LegalPotionRulesAndExplicitRiskRules)
    met = eligible.Where(w => w.ProgressAtDeadline >= ctx.SignedRemainingTarget)

    if met is not empty:
        # 固定目标以后用成本，不使用旧 3 HP 轴。
        # 成本一致时取更高真实进展，避免返回已被支配的弱达标点。
        chosen = MinBy(met, (Cost, -Progress, StableBundleKey))
        return ConditionalWitness(chosen)

    # 不把 D_requested 降到刚好找到的输出，不标为 Infeasible。
    chosen = fallback.ChooseOnFixedCompletedBoundary(completedFacts, ctx)
    return UnknownTargetWithBestAvailableAdvice(chosen)
```

在固定比较集合/参数后建立稳定次序，不能在两两比较时各自选最有利 K 或 D。成本中的尾值和事实必须可分解显示。真正死亡、资源消耗不藏回更早检查点，但某一坏后缀不应让同当前回合的另一好后缀失去资格。

### 10.4 费用与“共享”的限制

一次前沿减少的是**重复求不同阈值的工作**，不是保证比单目标 Beam 更便宜。支配检查、更多标签、代表保护和同边界闭合本身都有成本。把同一状态复制到四个配额桶，不应隐形增加四倍活分支；优先共享不可变事实与动作路径，不共享可变模拟器所有权。

外部 3/7/14 周期评测始终在搜索之外，不能把外部真实队友轨迹拿回搜索调目标。任何因 D 改动引起的更多血损/药水都按统一外部指标评价，不把更多见证、后缀更长或表项更多记成策略收益。

## 11. 最多三批落地：第一批具体交付什么

本节是后续实施建议，不是本次实施授权。每批都保留官方单人原路径、参数、缓存和行为；不自动操作，不自动重算，不扩大原请求总预算。

### 第一批：目标与见证核心，先做一个真正可用的 Q-equal / Q-team 原型

**这一批不做主动队友模拟，不做二分多次搜索，也不训练模型。** 具体工作：

1. 在现有多人分派增加 `Quota` 目标模式；原单人入口不进入新对象。旧 A 仅作显式对照。新模式完整旁路第 7.4 节列出的 3 HP 消费点，保留原始扣血/资源观察。
2. 在多人 partial 中增加 `QuotaContext`、有界 `QuotaWitnessTable` 与独立 `ObjectiveSatisfied` 查询。复用卡级枚举、合法选择、真实回放、完整当前回合和敌方阶段；没有伪胜利，没有缩 HP。
3. 增加最小阶段账本：真实绝对敌方周期、固定截止、任务目标和已观察净进展；新根重建一切预测。可先用当前受支持的普通敌人任务范围，不假装已解决全部复活/换形。
4. 同一次搜索可查询用户原始 Q-equal 和团队 Q-team 两个目标，记录谁的当前完整回合发生变化；这些是同一批付费见证的选择对照，不再开两个独立 solver 各领预算。
5. 建立 F0 incumbent：去掉软 3 HP 的进展—代价/本机尾值回退。未达标明确 Unknown；当前完整回合/反击尚未验证时不称“安全达标”。
6. 新增的是**新模式合同**：保持真实 HP 的攻防例、目标命中后继续结算、固定截止、Unknown 传播、同表多配额、强制用药、外部选择、取消释放和单人零进入。现有不变的成功实验无需仅为安心再跑；修改到的路径与新目标需要新的针对性检查。

最小源码切口：`MultiplayerSearchPolicy.cs`、`CombatBeamSolver.Multiplayer*.cs`、少量 `Phases / StateEvaluation / Retention / CombatPlan` 显式模式分派，以及 Runtime 的阶段账本捕获/过期校验。新文件最多先放一个 `CombatBeamSolver.Quota.cs` 与一个小型事实/账本类型文件，不启动通用规划器重构。

**第一批的能力边界必须公开：它改变进展与战损取舍，利用枚举共享见证，但在队友不主动的条件世界中，仍不能正确消费 U3 的队友易伤收益。** 它是有价值的可实施首版/强基线，不是完整协作能力已经验收。

阶段 K 与搜索的最大上限分离：到达目标评价截止只形成多人策略评价边界，不触发战斗胜利；真实终局仍走真实终局。首批无需为此修改官方单人的窗口或终局枚举参数。

**进入下一批条件：** 真实反击/配额状态没有混淆，3 HP 已从新模式全部移除，当前动作差异可解释，未出现额度扩张、资源所有权污染或单人进入。若这些语义失败，不继续堆队友情景。

### 第二批：只补最有价值的一段合法队友消费

目标是 U3、团队防御和救援的关键缺口，而不是恢复大型 D：

- 先完成 root ready 三态、显式 actor/choice 和分玩家资源事件合同。**这属于共享语义依赖，必须单列验证**；不能只改策略分数或删除 `RequireLocalChoice`。
- 对有限当前回合代表使用同一个可见信息的简单队友政策，限定当前回合剩余行动与受支持时序。未知状态明确条件或回退，不自动假设完美配合。
- 以团队结果更新前沿；默认不增加反事实基准模拟。如果需要解释或实验边际配额，使用一次付费共享合法基准，禁止重复计价。
- 把无攻击、已结束、另一目标、先后手变化、救援后不可行动、RNG 变化列为必要反证。外部选择仍是明确边界。

**进入下一批条件：** 在同预算下确实改变并改善相关当前完整回合，且没有在无消费、错目标和顺序失配例中制造虚假达标。不要求每个例都优于 A，但必须保留并解释退化。

### 第三批：冻结 Qε 与 F0，决定是否值得默认启用

冻结目标、K、代价和保留规则；机制消融尽量固定同一目标口径，避免把改目标与加前沿的影响混为一谈。用新的未参与本轮设计的战斗根或人工预留根，对比：旧 A、原始 Q-equal、Q-team/Qε、F0；只有有余力且输入变化时再将原 D 作为复杂度上限对照。R 固定保留回归，不再当新盲测。

统一外部 3/7/14 周期执行**同一个已选当前完整本机回合**，采用相同外部队友政策/行动顺序测试，记录生命、净进展、减员、用药、救命、任务按期达成/拖延、条件失效、费用与峰值活状态。固定逻辑预算和固定墙钟预算分别报告，不换单位掩盖计算税。另做单独的阶段闭环检查：按相同的模拟手动请求时点重新规划，检验是否拖延/重置目标；这一项与“只评价一个当前回合、之后使用共同续行”的主质量实验分开，不能混成一个结论。

**停止/降级条件：**

- 出现缩 HP、伪胜利、未结算反击、错误 actor/choice、单人变化：停止新模式，先修语义。
- 前沿保护/配额扫描反复挤掉更好当前回合，外部表现劣于 F0：减少见证维护复杂度或采用 F0，不扩大 Beam 来遮盖。
- Q-team 的共享队友层再次出现“R 式外部质量相同、成本明显更高”：不默认启用队友层；保留 Q 核心和便宜条件。
- 严格配额在目标边缘反复导致 19/20 式不值的额外代价，或阶段达标后持续少打导致成长压力恶化：修改目标政策，必要时采用 F0，而不是称作“用户愿意进攻所以合理”。
- 新算法主要增加显示长度、见证个数或内部达标率，没有改善统一外部结果：不算成功。

## 14. 最终交接结论

**采用配额思想，而且把它提升为首版核心；但采用的是“真实战斗上的阶段任务约束 + 有界 Pareto 见证”，不是“把怪物血量除以人数再套单人胜利”。**

第一批先让现有枚举在新多人目标下工作：去掉所有 3 HP 偏好、保留真实 HP、完成当前回合与反击、单次搜索共享目标见证、固定任务截止、Unknown 如实报告。第二批只补当前回合最必要的一段共享合法队友消费；复杂 D 不再预设必须上线。第三批冻结测试决定 Q-team 是否比便宜 F0 值得，不用更大预算替算法兜底。

用户原始 `H/N` 直接配额值得作为强基线保留；严格等分、刚达标就停、反事实重复计价和二分把未找到当无解均不接受。默认团队任务允许本机用易伤、救援或防御承担有效责任，而不是为了个人伤害配额抢打无关目标。

**没有新实验证明 Qε 优于原 D/F，也没有新实验证明移除软 3 HP 的 F0 保持旧 R 成绩。** 本次交付的是基于既有负结果、用户本地反例和定向源码复核所作的明确优先级修订。原 S10、F10/F12、Q11、预算税和本报告的配额代价断崖都继续有效；生产 C#、原生差分、ready/actor/choice 合同与真实联机仍需后续实施后验证。

本次未运行新实验、未改旧结果、未修改仓库、未推送或发布。
