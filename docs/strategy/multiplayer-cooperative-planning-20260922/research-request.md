# 多人协作策略重新设计：6 Pro 研究请求

日期：2026-09-22。唯一当前源码：`95fd98572884c1f2da97ffd5120167815fca6403`，fork `0.43.6`，分支 `codex/multiplayer-advisor`；官方单人基线 `3f4002bd / 0.43.2`。

## 用户的新问题与研究范围

用户实际多人游戏的反馈：高血量敌人很少能在搜索窗口内全部击杀；建议常常先防守，不愿打易伤等团队收益大的牌，或为了有限窗口内少受伤而放弃攻击，最后被成长型敌人压垮。用户认为不能继续围绕单人的“先找到击杀、再优化战损”思路做微调，要求深入查论文、利用计算机枚举优势，设计独立的多人策略。

这是新一轮研究和设计，尚未授权实施或发布。上次未复现的神化/蜡制遗物 Fork 兼容性问题暂停，不混入本次策略问题。只允许本机装 Mod；队友是正常操作的真人，本机也只手动请求和手动操作。

旧研究的每周期 3 HP 优先级、队友永久不主动行动、固定 14 周期及最终只计已兑现伤害，**都是这次应当审查的现役设计选择，不是研究不可改变的硬约束**。请明确列出建议改变的政策及其代价，不要因为旧规则而把结论再次缩成原样保守回退。保持可选旧政策用于实验对照；任何落地变更等用户后续确认。

## 必答问题

1. 当前最大错位来自世界模型、目标函数、搜索覆盖还是输出决策单位？逐项给源码证据。特别检查 3 HP 的词典序是否可让少受 1 点伤害压过实际胜利或重大团队收益；不要把这些都叫权重不足。
2. 如何像多人玩家一样做决策：当前回合优先级、合理卖血、集火减员、压血线、易伤/虚弱/团队防御/能量/抽牌收益、队友资源利用、怪物成长压力，以及长线能力投资回本？把这些转换为可枚举、可度量且不重复计价的对象，不依靠语言模型在线猜牌。
3. 什么是适合本项目的技术组合？至少比较：完整回合动作束 + Beam/枚举；截断 rollout/滚动时域控制和终端价值；MCTS/ISMCTS/PUCT；策略组合/脚本化动作抽象；临时组队与队友模型；风险敏感/鲁棒规划；离线学习价值函数。给原始论文/作者文献链接、适用条件、不能直接继承的保证及不推荐原因，不堆方法名。
4. 设计一套首选方案，而不只是微调现役。建议考虑“本机当前动作束广搜 + 少量合法队友情景 + 公平续行评价 + 滚动重规划 + 终端威胁/能力价值”，但必须独立反驳它并比较替代。队友可能先手/后手/已结束回合，行动顺序会改变增益兑现与集火；有限情景不得被当作真实发生。
5. 没有真人数据时如何构造队友模型、如何不高估其配合？何时允许使用冻结的队友牌堆，未来抽牌可见性怎么限制？不能用“固定每回合扣敌人 N HP”伪装合法模拟，不能给自己完美读心的后见之明，也不能对每条自己路线单独选择最配合的队友。未知适配语义继续明确边界。
6. 不依赖战斗算完，怎样合理评价被截断局面？区分累积造成伤害、敌人剩余 HP、危险单位死亡、未来避免伤害、队友增益边际贡献、资源和战略投资；防止伤害/击杀/减伤三次计价、治疗刷分、重复叠增益刷分、盲目卖血、对 boss 高估无用控制，以及过分保守的 worst-case 再次逼成龟缩。
7. 风险目标如何设计？已知当前回合死亡、低概率情景死亡、未来不确定死亡不能混为同一事实；哪些是硬约束、软代价、偏好？给可解释的参数与默认标定方法。固定 3 HP 可以成为旧模式或软锚，但不要未经论证作为所有路线不可跨越的第一轴。分别考虑本机生存、全队生存、复活和药水成本。
8. 充分利用枚举：如何覆盖多张牌的顺序/目标/选牌组合，安全合并等价状态，保护延迟团队收益，避免在第一层剪掉增益？回合束不能只由贪心脚本产生；脚本适合哪一层？怎样处理循环、资源生成、动作中途需要队友决策？
9. 同预算评估和根动作选择：公平初始份额、逐步加样/racing/简单遗憾、scenario index 与 RNG、不同深度的公平性、停止时的有效 incumbent、内存与取消所有权。所有准备、队友搜索、续行和评价都扣同一请求预算。不能把节点单位差异或更长等待伪装为算法优越。
10. 给 C# 职责边界、核心类型、伪代码和最多三批实现路线。保持官方单人路径/参数/行为隔离；不替队友执行，不自动重算。真实引擎重用，不为策略复制一套战斗规则。哪些需要新的共享语义能力必须单列。输出建议可注明依赖队友与风险，但不保证 14 周期安全或全局最优。

## 实验要求

请实际运行一套小型、可复跑的抽象协作卡牌实验，包含动作顺序、每人能量/手牌、定向增益、队友计划、敌方行动和成长；若模型无法覆盖某一生产特性请直说。抽象 A 应明确只是现役关键政策的缩减复刻，不能叫实际 C# 基线。

至少包含：易伤先于队友攻击、队友本回合已结束/没有攻击、队友打另一目标、怪物快速成长时卖血抢杀、确实应防守的致死威胁、危险小怪减员与纯总血量冲突、长线能力能/不能回本、队友提前杀目标、重复增益和过杀、救援与资源代价、队友行为模型失配、窄 Beam 组合丢失、预算很小时复杂方案反而退化。

比较 A 现役关键政策缩减、只改目标、加入队友模型、加入回合束/续行，以及一条替代搜索器；不要求所有新方案都好。至少独立留出测试情景，做去掉队友模型/终端值/风险处理/覆盖保护的消融。真实记账候选生成、队友规划、状态转移、rollout、评价与用时；同一总成本对照，并做有限预算敏感性。最终评价采用真实执行/固定未知队友策略推进的统一外部标准，而不是各算法内部自评分。区分抽象正确性、抽象策略结果、生产可达性、原生差分、真人联机和胜率。

给一个反对首选方案的最强反例，说明什么结果会让我们放弃它。不能用几个人造获胜例宣称超过人类平均水平；这需要后续玩家数据和盲评。
