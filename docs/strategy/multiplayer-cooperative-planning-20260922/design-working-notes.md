# 多人专用规划：本地候选设计

这是在收取 6 Pro 两轮最终交付之前形成的独立设计草案，保留思路来源。两轮均已完成；最终采用判断以本目录 [README](README.md) 的结论为准，不是现役行为说明或实施授权。本文 Q/F/S 是本地设计代号，其中 F 指共享前沿，与外部已运行的 `F_cheap` 或新回退 `F0` 无关。

用户后续明确不要队友行为预测；本文第 3 节及其他主动队友策略、反事实贡献和协作续行内容因此仅作历史候选，已从当前计划移除。当前方案只规划本机行动，队友未来操作留作未知，详见 README。

## 目标变化

彻底移除“每周期损失超出 3 HP 就在所有进攻收益之前受罚”这一默认目标。研究不要求维持该政策；旧版只保留为实验 A。真正要解决的是：在不确定的真人协作中，本机现在怎样出牌，能让团队更容易完成战斗，并付出合理的生命和资源代价。

本轮不以“增加到 28 回合”作为主方案。当前回合精确枚举很有价值；越远的未来，队友选择、信息和行动次序越不确定，应通过续行和局面估值利用计算，而不是假定一个十四周期未来必然发生。

## 1. 决策单位：当前牌序加条件边界

本机候选由真实引擎逐卡生成，涵盖顺序、目标、同名不同实例、费用、选牌、药水和合法停止点。候选是完整当前本机回合；如需队友插入动作才能继续，则截成明确的条件边界。未来动作只是评价用，不承诺真人能按整段脚本执行。

只保留“攻/防/铺垫各一个”可能过粗。探索通道要至少容纳有实质差别的目标击杀、单体与群体、即时救援、可被队友消费的控制/支援，以及费用/抽牌组合。通道代表不是奖励：保下来后仍由完整结算决定优劣，防止重复叠加增益刷分。

可证明等价的完整状态与相同信息/目标标签可去重。伤害相同但打了不同敌人、给了不同队友资源，不能只按本机摘要合并。Pareto 前沿是最终候选权衡工具，不替代未来状态等价性。

## 2. Q/F：先做用户提出的配额强基线

每个请求冻结目标 `(贡献口径, D, 截止周期 K, 风险与资源约束)`。真实胜利始终独立；达到 D 只是目标已满足。所有候选在同一 K 或同一完成的评价批次比较，不拿某条第一周期与另一条第十四周期的累计伤害直接比较。

初始基线可使用直接有效伤害配额 `D = 根剩余有效敌人 HP / n`，并给固定截止 K。这不是“把怪物血除以 n”，也不是永远人人同等分工。它的主要用途是回答：只换目标、沿用现有合法搜索能力，能改善多少；具体 D/K 后续通过训练根和留出根选择。

若每次手动重算都把截止再顺延 K，仍可能不断选择“这回合防，最后几回合再输出”。实验必须区分请求内固定时域与跨请求固定阶段目标。后者只能携带明确的目标/已观察贡献账本，重新捕获真实根并重新评估；不复用旧分数或旧预测状态。另一候选是用经过校准的末端威胁价值消除拖延，要用整场执行验证，不能仅凭公式宣称解决。

推荐 F 在一次搜索中保留已发现的输出-代价前沿，并形成多个配额的见证。一个见证可满足多个 D，已有搜索工作不作废。若需要继续优化阈值，只对尚有机会的缺口追加工作。目标未找到报告 Unknown，只有完整穷举或安全上界才声明不可达。

达到配额后，仍模拟本机当前回合结束、合法队友阶段与存活敌人反击；远期截断留下估值。不能设 `AllEnemiesDead = true`，不能套用真胜利下的免费战后治疗或掉药。

直接伤害配额对辅助角色是有意保留的弱点。F 是必须击败的简单对照，也可能适合不支持主动队友情景的根；不能因此宣称它已解决易伤、救援和分工。

## 3. S：用合法队友策略评价团队结果

在同一冻结根建立少量明确风格的队友策略，例如按当前可见信息争取减员、保住近端生命、按既定目标输出。策略根据其可见分支状态选择合法卡牌；目标被杀、能量不足或手牌变化时，按固定规则重新决策，不能跳过非法动作或凭空扣敌人 HP。

同一轮所有本机候选使用相同队友策略集合、权重和外生情景。不能替每个本机候选挑它最喜欢的队友；也不能固定一串只在某条候选后合法的队友动作，再跳过不合法部分。独立测试使用未用于调参的队友风格及切换行为。

队友“本回合已结束”属于可捕获事实；“未来偏防守”属于模型。不能混为概率。无训练数据时，几个情景只表示敏感性，不输出“95% 安全”“死亡率 2%”等统计承诺。完全不出牌可作为压力情景，不能无限权重支配所有正常协作路线。

未来抽牌和未知行为通过信息一致的观察接口处理。在同一个可见历史上，策略不能因为底层取了不同隐藏牌序，就提前出不同牌。用相同随机种子配对只能控制比较噪声；若动作会改变随机调用序列，不能强制对齐成相同抽牌结果，须保留原引擎的实际分支 RNG。

### 团队贡献如何入账

优先评价团队结果：某条路线让队友多打的伤害已经反映在敌人血量、死亡时间和避免的攻击中。另算易伤固定奖励会重复计价。

若为了配额解释需要贡献归因，可在相同队友政策下计算本机行动相对固定参照的团队增量。该差值包括对队友机会的影响，可以为负；它不必等于本机直接伤害。反事实模拟计入预算，未算则不伪造。各玩家的边际贡献不保证能相加，不能把它当自动公平分摊。

救援与团队格挡直接改变团队存活、HP 分布与资源。没有必要把救援强行换算成“我打了多少伤害”；若使用配额过滤，应保留关键救援资格并由最终团队目标评估。

## 4. 近端精算，远端续行，末端评价

建议以当前玩家阶段及一到数个敌方周期为精确主干，再用有界的合法基策略续行。具体周期数和分配应由固定预算实验选择，不是在本文拍板一个新常量。

关键不是“预测更短”，而是把相同计算量用于更多当前牌序、合理队友变化和有用续行。若某能力第七周期才回本，可以追加该候选的同条件续行；不能在未覆盖竞争候选时直接按更深终点宣布它更好。

一种统一的最小化形式是：

```text
J(plan, scenario) = 已模拟的团队生命/消耗品代价
                 + V(截断局面的剩余战斗代价)

Select = 在合法性、近端生存及明确资源约束内，
         比较各情景的 J 与风险敏感性；
         配额模式额外要求指定截止内的贡献达标。
```

`V` 需要看到逐敌血线、行动时点、可杀性、成长速度，以及团队未来抽牌/能量/防御能力。实际胜利令剩余代价为零；实际失败有失败代价。它是近似估值，不是假造已发生伤害。

不同时堆“造成伤害奖励 + 击杀奖励 + 未来减伤奖励”：若剩余战斗代价已因危险小怪死亡而降低，重复加这些奖励会过度偏好该路线。不能因血量汇总相同就把濒死输出手与满血队友视作一样。治疗只计真实恢复及后续代价，不按次数奖励；有限生命/资源循环不得刷分。

成长压力可由敌方未来可行动次数和每次威胁进入 V，或显式缩紧阶段目标的截止时间。两个机制若同时启用，要做消融防止重复加压。按敌方类型手写“永远攻击某怪”不是主设计。

## 5. 风险与达标的关系

区分三类信息：确定的当前致死、指定合法情景下的近端致死、长线模型推测的未来致死。第一类通常作为不可采用边界；后两类保留情景与时间标签，不能自动等价于当前玩家已经死亡。

本机死亡、全队失败、队友倒地和消耗复活资源不是同一事件。多人可能以本机倒地换取团队获胜，不能用单人胜利定义暗自决定这个偏好；第一版可默认保留本机存活，并在报告注明可能排除牺牲打法，后续再由明确政策决定。

在风险允许范围内，愿意受伤换减员/压血应当可能获选。代价阈值应根据当前生命、下一威胁和整场目标标定；不再使用每周期一律 3 HP。也不把无限卖血当默认。若所有方案都很危险，返回风险最低且仍推进战斗的已验证方案，并显示条件，不伪装安全。

## 6. 预算与任何时点可交付

候选先取得共同的基础评价，再追加情景或续行。维护有界根动作集合，按阶段作成对比较或顺序淘汰；新候选必须付足相同基础评价成本才能挑战当前结果。

没有完整基础评价的候选不进入最终排名；但它占用了多少工作、为何没能完成，应保留诊断。初始低成本结果不必使用旧 3 HP 政策：可以使用 Q/F 的已完成可行见证。若连第一轮真实敌方结算都未完成，只能发布明确的未完成建议。

所有工作来自一个请求预算。中断时输出最后一个完整评价批次的见证；不能提交半条情景、补偿额外搜索时间，或用后台无限补算制造更好结果。更复杂 S 必须在小预算反例中接受退化事实。

## 7. 实现责任建议

保留单人 `CombatSearchCoordinator` 原路径。在既有多人分派点新增独立协调器；新策略候选、情景、前沿和预算属于单次请求。公共模拟器不承载候选评分。

最小职责可分为：多人目标/风险快照、当前行动束枚举、队友观察与政策、情景续行评价、根方案选择。类型名待实施时沿现有命名约定决定，不为研究先创建接口空壳。

语义依赖单列：ready 根捕获、active actor 与外部选牌解析、行动交错、未知信息观察、跨队友资源历史。每项先有最小 actual/simulated 与 Fork 合同，才能用于策略比较。复用同一个 `PredictionForkContext`、取消排空和 simulator 单一所有权；不把模型读取移回 live。

建议最多三批：先实现 Q/F 目标与前沿并保留 A 对照；再补齐队友情景语义及 S；最后根据留出根结果选择默认、校准截止/风险/预算与展示条件。若第二批的收益不胜过第一批，应保留简单方案而不是为“大改”强行上复杂搜索器。
