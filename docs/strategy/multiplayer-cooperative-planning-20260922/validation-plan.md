# 后续落地的可证伪验证计划

本文为待执行方案。已有本地证据仅见 [`local-probes/`](local-probes/README.md)；不能把下表写成已通过。

## 比较对象与共同条件

应保留现役 0.43.6 作为 A，并至少比较三类真正不同的候选：

1. **Q：贡献配额。** 固定真实战斗状态与截止时间，在达标路线中优化战损；不按 3 HP 优先，不修改敌人 HP。
2. **F：一遍枚举的权衡前沿。** 与 Q 使用同样目标和模拟模型，区别只是共享候选、见证与预算，避免逐阈值重启。
3. **S：主动队友情景与续行。** 与 F 使用同样本机候选范围，新增合法队友策略及终端评价，以识别收益来自模型而非多给算力。

这里 F 是本地前沿代号，不是首轮外部 `F_cheap`。另保留新 `F0` 便宜进展/代价及本机续行回退；它已经删除 3 HP，同样未运行。区分直接 `H/n` 配额、团队净进展目标与严格/弹性选择，不能把目标、模型和搜索复用的收益合并归因。

更换成 MCTS 的 M 应与 S 共享目标、队友模型、末端估值和时间上限，才算搜索算法对照。不能把“新 MCTS + 更好评分 + 更多时间”合成一个结果后归因给 MCTS。

所有准备、候选生成、Fork、选牌、队友规划、回合推进、末端评价、重放、排序和发布都计入同一请求。报告实际墙钟、展开/转移/选牌次数、峰值存活分支与停止原因；抽象工作单位、生产节点和毫秒分别列出。

最终外评固定完整的已选本机当前动作或条件策略，然后用评估方的队友与后续政策推进。不得让每个算法用自己的预测终点、权重或设想的完美队友宣布获胜。

另外单列连续手动重算的闭环协议，检验固定阶段期限、可倒退净进展和任务重建；旧外部只选一次动作的协议不能代替这一项。旧 R 的八个根现在也参与了设计依据，只作固定回归；最终新方案必须使用新的留出根。

## 分层执行

| 层 | 最小输入与目的 | 通过标准 | 不能外推 |
|---|---|---|---|
| 语义前置 | 两玩家，本机任意索引；主动队友攻击/增益/选牌，ready/死亡/额外回合，父子 Fork | 相同明确动作下 actual/simulated 全状态严格一致，根不变，合法 actor 与事务边界成立 | 不证明搜索能发现好动作 |
| 当前决策 | 固定短预算的目标根 + 一个防御哨兵 | 新候选进入、保留、获得相同评价并实际被选；没有隐藏超预算 | 不证明整场更优 |
| 时限/配额 | 配额达成仍存活敌人、不同达标周期、重算与已付贡献 | 不触发假胜利，统计无重复；Unknown 不转不可行；终端按真实敌方阶段 | 不证明选定配额最优 |
| 同预算质量 | 配对 A/Q/F/S/M，固定根和评估队友，留出怪物成长/牌序/角色组合 | 分开报告胜负、团队生存、HP/资源、击杀时间和伤害曲线；逐负例解释 | 不可用内部评分代替质量 |
| 信息边界 | 不同隐藏牌序却同一观察、队友不同风格、未来换目标 | 当前可执行策略不偷看隐藏状态；不同分支不会伪造信息到达 | 不证明真人分布校准 |
| 单人隔离 | 现役官方同根哨兵与入口计数 | 完整路线及非时序字段不变，多人入口零进入 | 不代表全角色回归 |
| 真人评价 | 后续收集获得授权的多人根与独立玩家盲评 | 评估者不知算法，记录可执行性/配合要求/胜负；覆盖多种队友与难度 | 少量精选根不能声称超过平均人类 |

默认遵守仓库 L1/L2/L3 路由：新 actor/choice/Fork 属单列语义合同；策略用短搜 + 哨兵，最终候选才做所需增量或整场。普通无人请求不超过 120 秒；超时缩小夹具，不放大内环等待。只有用户授权可见性能验证时才运行可见 Steam。

## 必留反例

| 反例 | 希望区分的问题 |
|---|---|
| 易伤之后队友有足够攻击；队友已结束；队友改打另一目标 | 团队增益须依赖实际机会，不能固定加分 |
| 同样总伤害，危险小怪死亡与首领少量掉血 | 总伤害不是唯一团队收益 |
| 成长快的敌人；普通稳定来伤敌人 | 进攻压力需要随时间变化，不能恒定卖血偏好 |
| 近端确定致死与远期条件性致死 | 避死事实与模型风险分层，不把全部未知未来当实际死亡 |
| 打够配额但没有防御，仍活着的敌人致死 | 虚拟达标不能改写真胜利 |
| 辅助/救援角色；队友已经濒死且有高输出 | 直接平均伤害配额不应排除救援 |
| 长线投资来得及回本；目标被队友提前击杀；战斗提前结束 | 收益兑现与投资机会成本 |
| 已有易伤/控制，继续重复叠加；过杀；Boss 无效控制 | 不按图标、层数或名义伤害刷分 |
| 治疗自损循环；复活；敌人回血、转阶段、召唤 | 贡献/代价账本不刷分，敌人集合口径稳定 |
| 相同可见状态、不同未知未来牌序 | 防止策略融合和后见之明 |
| 玩家阶段交错：先增益后队友攻击；队友先攻击 | 当前动作束不应被误当成现实原子事务 |
| 队友策略在中途改变 | 模型失配与重新计算后的适应能力 |
| 窄 Beam 下先铺垫后兑现的组合 | 探索保护不能只靠最终评分 |
| 极低预算、很多根候选、昂贵选牌 | 复杂模型会抢走本机枚举；退化必须记入结果 |
| 二分的某个阈值搜索超时、另一更高阈值有见证 | 不把 Unknown 当 Infeasible；已有见证允许复用 |
| 重算前后已付伤害、队友死亡、怪物转阶段 | 配额及人数分母的口径不能漂移 |
| 输出 19/战损 0 与输出 20/战损 10，目标 20 | 有界前沿本身不能消除硬门槛代价跳变，须比较目标和选择政策 |
| 纯支援被无队友模型先筛掉；仅部分候选得到队友续行 | 支援保路与共同已完成评价，避免选择偏差 |
| 初次达标后敌人治疗；个体未达标但全队已清场 | 不锁死净进展，不把个人配额置于真实任务结束之前 |

## 停止或否决条件

任一语义错误先停止该根的策略比较。若 S 的优势只出现在与规划器完全一致的队友，换留出风格就消失，则不能默认采用；如果同预算因队友搜索挤掉关键本机牌序，必须收窄情景与续行成本。若 Q/F 只在随意降低伤害目标后显得更省血，不能称改善；若任一候选以更高本机/团队死亡代价换取表面高输出，需明确交易而非汇总为正收益。

“超过人类平均水平”是后续验证命题：需预先定义玩家样本、难度、角色/Mod 栈、信息条件、计算时间和度量，做独立盲评或实际游戏比较。本文没有给出该结论。
