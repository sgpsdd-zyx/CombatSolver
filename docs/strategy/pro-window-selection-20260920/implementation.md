## 采用边界

采用 [6 Pro 设计](CombatSolver_Multiplayer_WindowSelection_20260920_Design.md)的受限 C：完整当前回合代表集合、已有具体续行的最深共同检查点、原风险顺序、已知坏延长抑制旧祖先、费用门禁和 A 回退。当前权威算法说明位于[多人指南](../../multiplayer-advisor.md#未击杀时如何选择长线方案)，职责图位于[架构地图](../../ARCHITECTURE.md)。原始报告、抽象脚本和研究阶段数字保持原样；它们不算本轮真实游戏测试。

| 6 Pro 建议 | 本轮处理 |
|---|---|
| C 的完整回合身份和全代表覆盖 | 已接入 `CombatBeamSolver.MultiplayerWindow`，严格区分牌序、实例、目标、选择、药水槽和实际结束边界；作用域是当前发布前候选及仍保留的上一层/结束回合，2 至 Beam 个代表 |
| 祖先抑制与具体后缀风险 | 在同根纯动作路径索引上只抑制已被具体延长的祖先；原质量比较器继续读取完整后缀的已知风险，好兄弟独立保留 |
| C 的共同周期动作成本 | 只在周期严格升级时启用，沿释放后的父链定位真实敌方周期边界；完整终局仍用全路线成本。A 和中间保路保持完整动作数 |
| C 的预算与基准保护 | 单次发布 65,536 元数据计费单位，截止来自当前请求；收尾估算包含两次整条路线和全部必要续用前缀，按平均转移成本留两倍系数。新选择不得比 A 增加已知本人死亡/救命次数/超额等级 |
| 跨发布持久代表注册表 | 未建长期表；每个发布点从现存池重新冻结，显式加入仍保留的上一层及已结束回合，避免索引持有旧树或把已裁剪方案当作仍覆盖 |
| D 主动补齐、E 曲线加权、按候选数选深层 | 未采用；不扩大 Beam/节点/时间，不新增队友行为概率或未来估值。没有恢复更早被剪掉的牌序 |

实现为多人 Search 政策。`Phases` 只在原多人分派调用新发布准备函数；终止池局部压缩仍调用 A。`MultiplayerEvaluation` 将原质量顺序与末级动作数分开，以便 A/C 共享所有风险/收益比较。Engine、Prediction、Runtime、UI 和第三方登记点没有行为改动；单人官方最终比较器没有变化。
