## 结论与建议

**优先主方案选 C 的严格版本：以完整当前本机回合计划为代表单位，维护“所有在册代表都有实证检查点”的共同完成层，再原子发布该层结果。** 简称 **C_cover，首回合覆盖的共同层发布**。它不奖励深度，不增加 Beam 席位，不预测队友主动配合；收益来自让已经付费算出的后续事实有资格影响当前出牌，而不是给未兑现能力牌加权。14仍是上限，3 HP仍是原排序目标，手动执行和官方单人路径不动。

**低成本回退是 A：当前 `851c1521` 固定14、原最终批次与完整动作数。** 不把 B 当作长线优化替代物，也不默认上 D 续行或 E 加权曲线。C 应进入下面两批最小生产试验；本轮证据**不支持直接宣称其全面优于现役或已可全量切默认**。这不是继续只做诊断：设计文档明确了可实现的数据单元、发布条件、改动位置和第一条生产反例。

关键证据有四组。W07中，A/B当前回合选即时攻击，C改选独立铺垫，统一第7／14周期敌方HP由 **546／504** 降至 **480／438**，同时第3周期由570变为588，存在清楚的近端机会成本。W39中，队友提前击杀铺垫目标后，C第14周期反而比A多剩 **18 HP**。W38在特意构造的382工作预算断点，覆盖扫描让C错过强首回合，敌方第14周期HP从A的 **432** 退化为 **504**。W40中，足够便宜且正确的续行 `D_fast_hold` 能改善当前计划，而同样算到14的 `D_fast_greedy` 完全失去这份收益。这些证据共同否定“只比第一周期已经足够”和“长一点／加一点组件必然更好”。

### 2.1 不能重新报告为旧缺陷的部分

最终R1/R2仍成立：资格在截断之前，同次批次固定比较周期并由最终选择直接消费。提前胜利／死亡不会再被旧检查点遮蔽；多人不会再因单人的满血胜利谓词停止；普通多人的14周期与双预算不是本次建议才要加的参数。上述“已修”是源码复核结论，不是本轮重新跑过旧840排列、216三元或原生战斗合同。

B的共同周期动作成本**确实仍只在离线实验**：`MultiplayerHorizonContracts.cs:408–528`构造真实回放路径，再在实验比较器中沿parent找该周期的动作游标。现役比较器第115行仍使用完整 `ActionCount`。该合同检验的是一个给定对象集合的同分语义，不证明生产搜索一定提升当前回合。

### 2.2 五个量必须各自记录

H=14是上限。`max_expanded_parent_cycle`是付费展开父节点的最大敌方周期；`max_generated_cycle`包括刚生成但未再展开的孩子；`selected_cycles`是所选具体续行的完成周期；`common_evaluation_cycle`才是本次比较收益所用时点。再加一项独立的**完整首回合动作串**，才足以判断当前决策是否改变。

W03提供非常直接的区分：A、B都已生成14周期候选。A选中1周期、B选中14周期，但二者共同评价仍是1、完整当前回合都为attack，外部3／7／14结果完全相同。B的53额外工作主要是最终长路线重放，不是本机输出改善。W30全终局池共同周期为14，选中胜利实际发生在1；14是上下文哨兵，绝不能写成“已验证14次受击”。

## 3. 按优先级整理的发现

### F1／高优先级策略缺口：短候选可以把已付费长线收益排除在当前决策之外

**S：** 正常候选的最浅正检查点决定收益时点；风险取完整可见尾部；末级动作数取完整路线。**A：** M01、W03/W07/W14展示：较深路线的收益不计，深层动作与风险却可能计入，从而选择即时攻击或较短版本。它不是比较器不传递，也不是“所有搜索都只看第一周期”。

生产可达前提必须同时满足：有一个**最终合格的正常浅候选**进入同批；它未被资格规则淘汰；较深的有利路线仍在可供发布的池中。浅候选可能来自最后cohort或某药水类别的boundary fallback，但二者条件不同。最后cohort通常只比前沿浅一层；只有节点或时间停止才回流，不能把内存停止一概算入。药水fallback只有最终池缺该类别时才补入，而且按历史Score更新，并不必然停在周期1。额外玩家回合boundary可能没有敌方检查点，此时也不必然把共同周期拉零。

W03系列特意让两条深续行在后面用药，而历史无药fallback保持1周期，模拟这个**类别缺失的发布形状**。玩具流强制给定后续药水动作，未证明生产三通道会在真实牌局把所有深无药续行都裁掉。因此这是“与源码入口条件相容的抽象反例”，不是具体游戏可达性的完整证明。

**最小生产反例：** 在冻结的高HP根上用 `Replay/Expand` 得到两个不同完整当前回合，各有真实第3或7周期安全后缀；再让真实有药／无药兜底条件或实际预算停止把浅节点带入**实际最终入口**。记录浅节点来源与资格、原批次共同周期、C覆盖深度、双方外部3／7／14结果。若实际入口根本无法形成该组合，应降低F1对该根的解释力度，而不是继续手工往池里塞对象。

**最小方向：** 用完整当前回合代表覆盖选择一个共同完成层；不先把浅风险抹掉，不把“已经更深”写成优先维度，不改3 HP排序。

### F2／中优先级比较口径：B不只是显示修复，也不是充分的长线方案

“仅动作成本对齐，完全不可能改善当前动作”这一说法太强。M01中，两个不同完整首回合在共同周期的战斗事实相同，但共同周期动作数不同，B确实可换首回合；M02只改变未参与比较的后续事实，B又可能选到更差方案。**任何末级同分项都可能决定不同首回合，不能由它位于末级推出无战斗影响。**

相反，W03–W14中初周期即时伤害严格领先，B根本不能奖励尚未兑现的铺垫。W03的A/B外部结果相同，只把所选续行从1延长到14。旧F12的结论在这个意义上仍成立：同首回合、同外部结果的后缀变化只记证据／显示，不计质量。

实现B不能凭估算动作数。现有检查点没有游标；可复用宿主的parent边界查找，缓存一次准确结果，并把查找与最终重放计费。终局仍使用完整动作数；零周期／无精确检查点保留原回退，不能假造0成本。它可作为C内部的同层口径，但不应单独作为这轮主方案发布。

### F3／高优先级覆盖问题：同层候选数量不能代表当前回合方案覆盖

M04用同一个低分支首回合的四条后缀填满“足够候选”，但另一个强首回合只到1；`C_count`自称完成3层，`C_cover`只能确认1层。主运行W26中，C_count在12层选择attack，而A/C_cover的强首回合 `late_combo`在统一14周期少剩72 HP。更大预算下C_count仍可能选已到14的弱setup，说明这不只是时间太少。

“足够”应是**本批在册、具备发布资格的不同完整首回合代表都有实证覆盖**，而不是节点数≥2、到达最深的路线≥2或两个动作族都有一个节点。集合本身受既有Beam裁剪限制；不能称作全合法首回合覆盖。新代表进入需要重新判定本批覆盖，不可悄悄从集合删掉高分支／未补齐的代表来获得更大的d。

**反对证据：** W28外部选择把一个代表停在1，C_cover也停在1并选择attack，而A对另一正常深候选可取14并选择更好的setup。外部评价在这里额外假定阻断随后会被正常解决；它不是生产可执行证明，却真实说明“所有代表覆盖”可能过度保守。主方案应将外部阻断视为显式不可覆盖原因，首批对此不启用C，直接走A；不能以此声称C在所有根均能升级。

### F4／高优先级证据规则：坏后缀不能擦除，也不能污染整个当前回合

M06和W22中同一个完整首回合有好坏两条续行，按具体续行保留风险、让好续行继续竞争即可。不要建立 `badFirstAction` 或 `badFirstTurnPlan` 全局黑名单。也不要在第d周期重建“没有尾部风险”的干净节点，把已知死亡／救命消耗／超额藏掉。

S证据是 `max(common, tail)` 风险与 `min(common, tail)` 存活口径；这不是对历史所有时点的全量“有人死过”账本。中间死后复活等所有权／历史语义仍需引擎差分。本轮不扩张成资源归属重构。已知死亡与资源消耗在当前比较中是事实；未知尾部是未覆盖，不等于0风险。W23的浅方案仍可获选，但报告只能说它有较少已知反证，不能说它被证明更安全。

### F5／中优先级预算问题：比较与续行的付费成本足以改变当前计划

`ExpandedNodes`不是所有模拟的完整工作量；源码一次父展开可计算多卡／选择分支，最后父名额的串行接受又有历史规则。最终释放后的路线还会完整Replay。D不能给每个代表另开一个拥有完整请求预算的solver；E不能免费扫任意多时点；C不能默默多保留一个拥有simulator的历史树。

W38在预算382时，A能准入昂贵的 `late_combo`，C/E的覆盖／曲线扫描与D的续行消耗让它失去准入，当前计划差72 HP。**重要反对解释：** 这是刻意放在准入断点附近的反例，并使用统一256单位的保守最终化保留；C总已花工作甚至小于A，因为大作业不再能入场。更细的可中断作业或更准确的重放报价会缩小该区间。不能把382解释成生产节点、毫秒或真实常见频率。

### F6／条件性残余：跨发布时点的压缩不是R1/R2已修范围

完成池在 `Phases.cs:2005–2016` 先按局部上下文压缩，之后再与前沿、类别fallback、最后cohort合流。后来创建新的正确批次不能恢复早先丢掉的路线。旧归档的4B候选反例仍说明这个逻辑可能性，但**本轮没有把该人工池复称为真实搜索已触发**。尤其全终局池不因共同周期哨兵改变完整终局事实，不能拿全胜利池硬套。

C必须在**同一次已经知道的发布候选全集**确定代表和深度，再裁剪。它不能解决更早的卡内、状态去重、三通道席位、已完成历史池丢失。若本地记录显示首次丢失更早，不能靠最终比较替换掩盖；第二批只考虑与该次已知联合池直接相关的小切口，不保存全树或承诺恢复所有历史候选。

## 4. 抽象实验如何保持比较有效

### 4.1 模型与生产差异

脚本有两个仪器。微型检查构造不可变检查点候选，移植当前比较的关键层级；用药只缩减成“至少一次本机显式用药”，不是完整槽位／保护指令实现。付费搜索则是**有限的完整当前回合计划流**：给定根上若干合法抽象动作序列，逐周期产生分支，限制在8个前沿句柄内，历史检查点共享。它不是生产卡级Beam、转置、并行调度、状态键或牌库的复刻。它能分离“已有证据怎样选”和“额外处理怎样抢工作”；不能给出生产胜率提升率。

计划流中的 `charge→channel→release` 真正在第三个抽象动作才兑现，`power→hit` 与相反顺序的结果由操作执行得到；但计划目录已经提供两种次序，没有证明生产Beam一定能发现第三步组合。高分支成本是明确给定的抽象枚举工作，不是测出的游戏组合耗时。相同seed用于可重放的情景实验；大多数确定性搜索根不消费随机数。

W27的 `extra` 只把玩家回合计数加一，未重建真实额外回合阶段和首回合签名分界；六臂都选择attack，因此不将该例作为“额外回合下完整首回合提取已正确”的证据。该边界仍须生产P2/P5验证。玩具敌方HP是存活HP之和，不是原生EffectiveEnemyHp所有阶段／复活特例的移植。`future_potion`是形成兜底类别的显式fixture开关；W03/07/14、W31/39各对照根的两种计划都采用同一开关。W29只用于资格边界，不据此主张不同首回合的输出改善。

每个策略同根、同seed、同14上限、同预算、同容量和同最终化保留。记录fork、动作／敌方阶段模拟、枚举、准入、元数据、比较、曲线／覆盖扫描、续行前缀重放、最终完整路线重放及释放排空。**预算相同不等于实际花完相同工作**；低于准入阈值的剩余额度允许不用。工作单位是声明的逻辑单位，不是Python执行指令或CPU时间；保守扫描上界与句柄峰值亦非真实内存字节。

### 4.2 统一外部评估

执行选中方案的**整个本机当前回合**，包括次序、目标、抽象资源操作和结束动作，然后所有策略用同一个合法状态反馈协议：后续普通攻击／结束，在资源成熟时兑现，而不是复用各自搜索给出的后缀。额外玩家回合在玩家计数中记录，只有真正敌方阶段才进入3／7／14观察。

外部工作另列 `evaluations.*.work`，不向搜索提供免费信息。终局／本机死亡以吸收状态延伸到统一观察点；未结束／选择阻断绝不这么填值。队友情景只在外部评估执行，没有各情景各自全知重选当前回合再取平均。

主要展示敌方有效剩余HP、本机累计扣血／累计超额、死亡／胜利。另列实际被扣掉的本机／队友HP伤害、过杀前名义值、击杀次数。正伤害累积可以被治疗刷大；队友补刀可以改变归属而不改变团队结果；因此不把这些相加成一个“质量分”。本模型不含真实逐敌威胁引擎，也不把M13手工威胁表冒充实战控制验证。

## 5. 实际运行结果与反例

表格深度列分别为“最深展开父／最深生成”和“选中续行／共同评价”；HP列全部是外部3／7／14周期，而非搜索各自终点。下述安全正例均本机超额0；涉及W32死亡或phase扰动时另行注明。

### 5.1 第7周期收益改变当前回合，而B只改后缀

C当前先铺垫，不能说所有时点都改善：第3周期少打18，之后多打66。W14把回本点移到14时，C的HP序列为588／564／438，相对A的570／546／504要接受更长的近端亏损。W03回本于3，C才在全部三时点都优于A。是否愿意用第3周期输出换第14周期输出，是本轮允许研究的选路时点政策，不是“纯bugfix”。风险优先级没有变。

### 5.2 机会成本：候选行数越多，可能越偏爱错误代表

W26预算570：A为 `late_combo`，C_count为attack，C_cover仍为 `late_combo`；统一14周期分别432、504、432。C_count的共同周期12甚至比C_cover的10更深，**深度更大且当前回合更差**。它直接反驳按数量定义“足够”，不依赖队友不确定性。

W38预算382的新断点运行如下。A/B准入强计划时仅完成其1周期，但它当下就多打72，外部后续也保留这72；C/D/E把工作花在其他地方，不能补回当前回合的遗漏。

### 5.3 D有真正的正例，也有错误续行与抢主搜额度的反例

W40把主搜的多分支枚举成本显式提高，`D_fast_hold`只走一个合法尾部，仍对所有动作、合法验证、前缀重放计费；它使用两条代表，同一剩余搜索额度的三分之一上限，不新增总预算。便宜模型不是实测的生产加速比。

| 策略 | 完整首回合 | 展开／生成 | 选中／共同 | 外部敌方HP：3 / 7 / 14 | 实付／总预算 |
|---|---|---|---|---|---|
| A | `attack` | 3 / 4 | 4 / 4 | 570 / 546 / 504 | 710 / 1000 |
| C_cover | `attack` | 3 / 4 | 4 / 4 | 570 / 546 / 504 | 730 / 1000 |
| D | `attack` | 2 / 3 | 3 / 3 | 570 / 546 / 504 | 720 / 1000 |
| D_fast_hold | `resource` | 13 / 14 | 14 / 14 | 588 / 444 / 402 | 775 / 1000 |
| D_fast_greedy | `attack` | 13 / 14 | 14 / 14 | 570 / 546 / 504 | 774 / 1000 |

这是对“D没有必要”的反证：正确、足够便宜的续行在7／14各改善102 HP，代价是第3周期少18。反过来，`D_fast_greedy`在第2周期把应等到7的资源提前以4伤害兑现，尽管比较也到了14，仍选attack。**错误基策略这里是失去相对D_fast_hold的收益，并未比A更差**，不能夸大；D比A实际退化的证据在W24预算520与W38的小预算断点。

当前D核心原型并未假定续行比主搜便宜，因此大量根只增加费用；补充快尾部才展示其竞争条件。本轮不据此为生产硬编码一种“永远攒到成熟”的新基策略，也不声称rollout定理能保护未知真人世界。[P3–P4]

### 5.4 E曲线不是无偏替代终点

W35中，C/A选择延迟setup，外部HP为588／564／392；等权3／7／14的E选择early_power，得到560／516／439。早期改善28／48，最终损失47。权重改为1:1:4或1:1:8后，E又选setup；4:2:1仍选early_power。权重表达的是何时重视剩余敌方负担，不是生存概率或真人动作置信度。

E不能把缺失的7／14点填成0；只用已经共同覆盖的锚点时，小预算相当于目标随锚点集合变化，可能出现新的切换。W24预算520与W25预算400中，E的扫描抢掉足以到达收益点的工作，退回即时攻击。收益曲线适合报告／宿主外评，不作为本轮默认生产比较总分。

### 5.5 队友扰动不是放弃长线规划的理由，也不是零成本安全证明

W39的两种当前回合分别是攻击另一只仍将存活的敌人，或给目标0铺垫。在队友不主动行动的条件模型下，铺垫长线更好；队友第2周期击杀目标0后，初回合攻击另一个敌人的价值保留，铺垫失效。

| 条件 | A 外部HP：3 / 7 / 14 | C_cover 外部HP：3 / 7 / 14 | 解释 |
|---|---|---|---|
| 无未来主动队友 | 470 / 446 / 404 | 488 / 364 / 326 | 长线获益，但近端少打18。 |
| 提前击杀目标0 | 320 / 296 / 254 | 338 / 314 / 272 | C三个观察点都多剩18；不是只有输出归属变化。 |
| 第2周期结束整场战斗 | 0 / 0 / 0 | 0 / 0 / 0 | 团队结果相同；A本机伤害18、C为0，只是贡献差异，不能写成胜率提升。 |
| 队友动作触发更危险阶段 | 529 / 505 / 463 | 547 / 423 / 381 | 两者第14周期本机扣血52、超额13；原idle的0损不是此情景的下界。 |

W31则特意保留“队友把本机本来要打的同一目标杀了”的版本：尽管本机贡献不同，外部团队HP相同。这是反对把个人伤害变化一律当团队改善的证据。W32的补防情景改变受击事实；W33同seed但加入队友事件后随机消费序列改变。它们都没有产生真人行为概率，也没有被搜索免费利用。

### 5.6 风险、阶段与极端边界

W22具体坏后缀的9扣血不会取消同首回合好后缀；W23未知短方案不是已证安全；M18确认额外本机回合不刷新敌方周期，已有根3加本周期1得到累计4／超额1。M07只检验缩减的显式药水资格，完整保护槽位仍须本地C#合同。

W30的早胜利保持完整事实。W32中各策略选到的长线均可能在第12周期死亡，这个根**不是安全优化成功**，也不能因全池终局哨兵为14而写成14周期安全；它展示在所有给定计划都差时比较器仍返回一个排序结果。无超额可行解时，不允许新增硬过滤把整个请求变成无建议而不说明政策改变。

W34保留反复造成实际伤害再被恢复的路径：伤害累积很高但敌方HP不下降，A与按剩余HP曲线的E都不会把它当最佳；M12展示错误使用“累计正伤害”会选反。多敌同总HP但威胁不同的M13只是机制表；真实集火、控制、救援仍须引擎生成后续受击证明，不新增重复计算格挡的加分。

## 7. 下一项最有区分力的本地实验

不是再收一批泛泛胜率，而是固定**一个高HP、真实完整首回合能以18左右即时伤害换第3或7周期确定收益**的冻结根。先用真实 `Expand` 记录两个当前回合的产生与首次裁剪；必须实际到达最终入口，同时记录浅节点究竟来自药水fallback、最后cohort还是其他来源。

以**同一解析后的多人预算**跑A与C；第三臂用仅排序B排除同分／显示解释。把三者选中的整个当前回合在同一原生根执行，再使用相同后续协议到3／7／14，分开做“队友不主动”“提前击杀铺垫目标”“补防”三种**明确合法操作**。比较首回合变化、风险向量、同一时点敌方HP及成本。

若已有14周期证据、A确被浅兜底拉到1且C在相同外评时点改善，支持F1与C的首批切口；若首次丢失在卡级第三步之前，C不是该根的解法，应停止扩大最终选路补丁并保留A。若补齐费用导致少发现一个强首回合，或C把已知坏后缀藏掉，立即回退。需要的最小宿主接入点和两批门禁见设计文档，不要求先做新Planner。
