# 单人使用多人军师：原生闭环实验（2026-09-23）

[实验设计](README.md) · [协议](protocol.json) · [原生根清单](native-root-manifest.json) · [精简证据与逐对结果](implementation-evidence.json) · [执行工具](../../../tools/MultiplayerExperiments/README.md)

## 1. 范围与当前状态

本轮前提是**只有本机玩家使用军师，队友独立决策**。测试程序代替双方输入，队友从不调用军师、不读取本机建议，也不保证按本机的计划配合。正式多人仍由用户手动请求和操作；生产策略、预算、单人路径及版本保持 `fd976376 / 0.44.2` 的行为。本轮只增加测试装置和记录，没有发布或启动可见 Steam。

这轮已从“首轮建议加固定模拟续行”推进到原生游戏里的完整牌组、双方真实出牌、交错操作、反复手动请求和原生团队终局。B批次预登记64条轨迹、32对，全部尝试：47条原生胜利、16条原生团队失败、1条超时。双胜的23对中，共享计分让本机战损改善3对、相同19对、恶化1对。4个受控配置来自同一模板组，独立真人来源仍为0。

## 2. 装置实际做什么

职责归 `src/Testing`。`ProtocolHost` 安装、撤销请求专用观察器和消融；`ScenarioBuilder` 在同一个原生跑局中创建两名玩家、写入整副战前牌组；`Executor` 驱动稳定动作和手动查询；证据经既有 `Writer` 原子写入。外部工具登记全表、分批启动和汇总。没有给 Search、Runtime 或模拟引擎新增队友策略。

本机身份始终为1，队友为2，不来回改 `LocalContext`。双方动作进入原生队列并检查行动者；本机复用 `FindCardForDeployment` 的状态键/出现序号映射、入队观察和 `NativeChoiceRuntime`。一次完成一项动作及其触发链后再调度另一方。实验没有调用整轮自动部署；每个搜索必须来自明确的 `Manual` 请求，自动计算/全自动保持关闭，并断言请求计数和部署状态。

每次手动请求从已经推进的原生状态捕获新根。同场保留生产战斗会话，独立观察账本对照其阶段、截止和实绩。普通质量格在搜索期间暂停双方输入；已捕获的根在搜索及后续原生动作后保持冻结。建议失效时记录原因、停止旧路线并额外请求，不猜换目标、不补一张同名牌、不跳过未知牌。

队友策略v1使用自己的当前手牌/资源与公开敌情。固定优先级是粗略即时击杀、必要时防御、Bash、Poisoned Stab、Strike、Deadly Poison、Inflame、Defend；“生存优先”在敌人当前攻击意图超过已有格挡时把防御提前。“即时击杀”只用登记基础伤害估算，未模拟力量/虚弱等修正。这是可复现的简易行为规则，不是最优队友。目标死亡后会重新选合法目标，手牌/资源变化后会重新决策，不沿用另一臂的动作带。

队友族共2类；三个行动顺序及两个重算节奏去掉等价格后为4格。整批先后行动没有多余的中途信息，因此只保留回合首次请求；逐牌交错分别测回合首次及队友批次后请求。两臂只切换 `Multiplayer.CreditSharedDamage`，包含该开关现有的前沿代价条件。每对首个请求比较完整根和全部非服务政策字段；不同本机动作之后，后续根、旧路线前缀和队友响应允许自然分叉。

## 3. 原根与测量口径

| 配置 | 本机/队友牌数 | 原生敌人开场生命 | 机制范围 |
| --- | --- | --- | --- |
| 本机唯一毒源 | 14 / 10 | 123 | 本机有毒牌，队友无毒牌 |
| 混合毒源 | 14 / 14 | 121 | 双方均可施毒，不从applier猜每层归属 |
| 防御/投资对照 | 12 / 10 | 125 | 无登记的无来源伤害机制 |
| 多敌毒源 | 14 / 11 | 105 / 48 / 83 | 三个敌人、转火与投资兑现 |

双方初始60HP，最大生命及初始遗物沿原生角色；没有升级、附魔或药水。普通怪物遭遇按原生人数规则缩放一次；没有人工压低敌人生命。战中正常抽弃、洗牌、消耗和获得资源，不周期补牌、补能量或补血。

每臂重新建局后比较完整全队 `ContinuationStamp` 与既有规范化 `NetFullCombatState.ToString()` 状态，再允许出牌。后者以带格式标记的UTF-8文本保存，并非原始网络包。这里证明的是登记战前配置的确定性重建，不是任意多人检查点恢复；原生规范化排除跨请求的选择/奖励序号，未声称逐字节包含所有UI和网络状态。真实根、初始遗物/牌组和原生生命值见清单，原始状态留在 `.local/multiplayer-native-20260923/`。

生命记录基于原生HP/最大HP/死亡事件，区分战内扣血、战内治疗、战后恢复和最终HP。例如首个完整终局合同中队友战内损4HP，60降至56，随后战后恢复至62；不能写成“没受伤还赚2HP”。终局来自原生 `CombatWon` / `CombatEnded`，不把本机死亡或请求超时写成团队失败。仅双臂都有完整胜利记录的配对进入条件战损表，失败仍留在全部32对的可用性分母。

350节点格为 `Beam12 / 3000ms / DOP1 / H14`。每次记录共同比较周期、阶段剩余周期、选中事实、观察到的最深周期、层级时间截止和真实工作量。`stageCovered`包含“可比且达到剩余阶段”或“可比的预测终局”；汇总把预测胜利/死亡另列。最大无来源暴露只覆盖经过事实观察函数的候选，不是穷举所有生成快照。**实际Score回退次数尚未接入，不能填0。**

## 4. 辅助合同与预算校准

- 原生闭环合同完成本机/队友动作、重复手动请求、下一本机回合、ready撤销、首项本机动作的实际/模拟完整全队状态差分及冻结根检查。
- 冷启动A/A曾因一个回合层级时间截止产生不同工作量，记为不确定。显式预热后的同政策A/A在完整事件、动作、查询、全队状态/RNG和健康记录上相同，只排除计时时长；不是仅比较最终HP。无毒对照的开关两臂也相同。
- 完整牌组的敏感根先校准再冻结断言。本机唯一毒源开场、队友尚未行动、350节点时，关闭臂首牌为 `POISONED_STAB`，开启臂为 `STRIKE_SILENT`；随后独立请求复现。它证明能检出顺序变化，不预先宣称这个方向更好。
- `RootIsolation` 在实际搜索会话已经捕获根、worker刚进入求解器且尚未展开时暂停worker，让队友原生打一张牌，再恢复。旧建议发布为过期，新手动请求发布为当前；个人账本均为0，总观察伤害由0变8，根不同且旧根保持冻结。这个合同没有覆盖任意展开中途并发、取消、网络重排或时延压力。
- 时间截短的Medium诊断只测本机唯一毒源的一对首请求，`Beam60 / 240000节点 / 10000ms / DOP1 / H14`。关闭/开启分别展开2608/2261节点、转移7679/6636次，均未触及时间截止；达到三周期可比事实。首牌分别为 `STRIKE_SILENT` / `DEFEND_SILENT`，与350格不同。该结果说明建议对预算敏感，不能把350节点的完整轨迹外推成正常预算的质量结论。
- 最终同进程多人→单人合同确认请求补丁、worker门闩、观察政策和计数全部释放，普通单人根与一牌胜利建议正常。随后故意用防御组开局参照比对本机毒组，得到预期 `root_mismatch`，0查询、0动作；启动器退出码1是负对照预期。最终Release构建零警告错误，分析器另外检查重复臂拒绝、未知分母、双败不算战损收益和未执行行保留。Bash职责门禁通过，PowerShell/Windows/Linux原生未运行。

## 5. B批次结果

结果来自 `pilot-b` 与仅续跑未执行行的 `pilot-b-remaining`，分析工具保留全部64行。公开协议的ID从草案v2整理为v3，原始B清单仍保存v2；登记的根、两队友、4组合、两臂及预算没有改变。原始输入、日志和全部查询保留本地，提交的精简证据含每对结果、每臂状态与逐玩家生命统计。

损血差为“开启减关闭”，只汇总双胜配对，是条件描述，不是总体收益。全表有23对双胜、8对双败、1对关闭超时/开启胜利；31对完整终局没有胜负差异。把未知终局作最悲观/乐观处理，关闭胜数为23到24、开启为24，差为0到1；这只是这32对的缺失结果界限，不能称真人胜率提升。

本机与全队的配对战损均为改善3对、相同19对、恶化1对。四个有变化的条件如下；其他双胜对均为0：

| 条件 | 本机损血：关→开 | 全队损血：关→开 | 手动请求数：关→开 |
| --- | --- | --- | --- |
| 本机唯一毒源 / 即时进攻 / 逐牌交错 / 队友批次后重算 | 6→1 | 21→16 | 12→13 |
| 本机唯一毒源 / 生存优先 / 逐牌交错 / 队友批次后重算 | 2→6 | 4→8 | 17→17 |
| 混合毒源 / 即时进攻 / 队友先手 / 回合首次 | 11→1 | 26→16 | 3→4 |
| 混合毒源 / 生存优先 / 逐牌交错 / 队友批次后重算 | 2→1 | 4→2 | 17→15 |

同一本机毒牌组只换队友族，就出现少损5HP与多损4HP的相反方向，说明队友响应和重算节奏确实影响效果。按队友分层，双胜条件的本机损血差之和为即时进攻-15、生存优先+3；不把不均衡且相关的条件混成总体均值，也不因此要求真人队友选择进攻。

31对可检查的首请求都满足完整根相同、政策唯一处理差异；7对首建议不同，15对本机完整动作带不同，只有4对改变双胜战损。防御/投资的8对均保持相同动作带与战损，观察到的无来源计数为0。含毒不等于一定改善；多敌组16条全部在第4回合原生团队失败，均记录2人死亡、没有复活。至少已实际经过“队友死亡后本机继续”的边界；没有覆盖本机先死后队友单独继续或复活。

63条有完整结果的轨迹保存402次手动查询、678项本机出牌、596项队友出牌；超时臂只有开场/日志，未补造其查询总数。402次均无全局或层级时间截止，选中事实均可比：307次达到剩余阶段且非终局、79次预测胜利、16次预测本机死亡。后16次不能算成功覆盖安全阶段，也不能以“402/402”声称全场搜索充分。实际Score回退次数仍未知。建议失效次数为0，说明本轮没有动态走到非法旧建议的处理分支；不能把该分支算为运行验收。

以上真实团队失败来自原生事件，报告协议的63个 `Passed` 只表示请求完成，不等于63场获胜。最终工作量汇总不包含预热、A/A、敏感根、Medium诊断和异常诊断。

## 6. 装置故障与环境旁路

使用原生Godot无头游戏，但传输仍为单进程。请求专用补丁只把军师的多人入口接到双人跑局，并使结束回合等待所有参与者；敌方开始仍走单进程确认，未测远端网络确认。既有无人测试已略过战斗规则教学；本实验另外略过首次洗牌教学确认以及缺少远端意图控件的队友出牌动画。实际洗牌和原生动作队列保留。

完整终局试跑逐项暴露了以下装置问题，原始失败记录保留：

| 记录 | 观察与处置 | 计入范围 |
| --- | --- | --- |
| `a-controls` 冷A/A | 工作量不同，记录到层级时间截止；增加独立预热，不加预算 | 不算确定性通过 |
| `a-final/07` | 第三回合首次洗牌等待教学确认，120秒无终局 | A的失败，不计B |
| `terminal-fixed` | 构建尚未完成时启动而加载旧DLL，发现来源不确定后停止 | 无有效测量 |
| `terminal-fixed-v2` | 最初只让教学节点创建返回null，原生调用仍等待它，导致异常；改为仅跳过教学任务 | 无有效终局 |
| `terminal-fixed-v3` | 原生回放/导出并发初始化普通字典缓存，在终局回调报错 | 无有效终局 |
| `terminal-fixed-v4` | 建局前主线程物化153个非空int枚举的只读缓存；完整原生胜利、战后治疗记录完成 | 辅助终局合同 |
| `pilot-b` 第12条 | 第二回合已完成两张本机牌后停滞，120秒未返回；原因未确定 | 主表保留失败 |
| `stall-diagnostic` | 同一条件在独立进程完成五回合胜利；不据此认定前次失败原因或替换前次结果 | 单列诊断 |

原生缓存预热只属于测试环境准备，没有修改游戏/生产并发实现。初期队友动画也曾报缺控件异常；最终旁路只覆盖该远端视觉通知。最终64格跨过两版测试记录器：前12格用完成时保存，余下52格改为每个动作/查询边界保存，以便下一次停滞留下最后状态；评分与队友规则未改，已完成配对没有跨这两版记录器混配。

原批每进程预热后安排16条轨迹，遇到超时后改成每进程预热加4条，只继续未执行行。未拉长120秒上限、未重跑成功格、未删去失败格。不能把缩小批次后成功当成已证明静态泄漏或多场复用故障的根因。

收尾补齐启动器的无结果凭证，区分实际到期与进程提前退出；没有凭证的无结果只算执行错误，不猜成超时。这条新写盘分支仅做脚本语法和合成凭证分类检查，未再人为启动一次游戏超时。原批超时发生时旧启动器尚不写该凭证，依据当时已观察的120秒停止补录，并明确标记为收尾重建，不冒充原始自动凭证。

## 7. 可参考程度与下一步边界

相对于上一轮，原生完整战斗消除了评价器与规划器共用影子引擎、只执行首轮、固定后续及把本机死亡当终局这几类实验设计偏差。现在可以定位建议怎样改变真实后续局面，以及独立队友的反馈怎样放大或抵消差异。

仍不能回答真人整体收益。两类确定性规则没有测量人类行为概率；相同初态下可复现不代表搜索知道队友下一步。随机失误、随机批次长度、支援、蓄力转爆发、多角色、多人数和真人数据都未覆盖。未知混沌应分成机制压力、行为多样性与真人校准逐层补齐，不能靠在这4个配置上重复换种子变成独立样本。

下一轮应先固定具有决策意义的正常预算比较，保留本轮所有恶化条件作开发回归；再增加独立来源的完整牌组和另外4类队友，特别是按公开HP/威胁切换行为、有限合法失误与晚爆发。随机源只归队友/调度器，不消耗游戏RNG，不供给军师。三/四人、死亡后继续及复活需要各自最小原生合同后才能计入对应质量范围。

当前尚未完成有意未支持牌/复杂选牌的负对照、实际Score回退次数、轨迹外隔离重搜敏感性、任意中途搜索并发/取消、全角色覆盖或可见性能。协议A/B因此按具体合同及可用性结果陈述，不写成“全部原设计门槛通过”。本轮不据这些受控结果改生产策略。
