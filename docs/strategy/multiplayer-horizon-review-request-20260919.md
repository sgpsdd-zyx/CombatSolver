## 用户要解决的问题

只有本机安装 Mod，其他真人队友正常手动玩。窗口太短可能丢失能力、星能或黑暗球等延迟收益；窗口太长可能沿着“队友不再主动操作”的条件世界线做很多无用工作，甚至使本机当前出牌更差。

本轮不是再次研究一般能力牌保路，也不是预先要求把 7 改大或改小。请回答：什么事实足以支持固定或自适应窗口，应该让多深的条件证据影响本机**当前动作/当前回合前缀**，以及在原请求预算内如何实施。

旧文档中的七周期是本轮基线，不是禁止研究其他上限的要求。用户已明确要求重新评估这个数值。每敌方周期 3 HP、本机手动请求与手动操作、单人隔离等其他边界继续有效。

## 对照与反证

请实际运行有界的标准库抽象实验，同时明确它们不是生产 C# 或真实联机。最低比较集合：固定 3/5/7/9 周期；一个有可解释触发条件的自适应候选；保留当前策略的回退。若合理主方案不是自适应，请明确反驳并给出更小方案。

实验固定根、牌序/RNG 假设、风险次序、Beam、节点及总工作预算；额外探测、前缀重放、队友情景和排序扫描都应记成本，不能为每个候选重新发一份预算。不同窗口需使用共同的外部评价协议衡量首动作质量，不准用各自终点分数横比。

至少覆盖这些机制，避免为每个卡牌建立目录：

- 即时攻防/救援控制组，终局和超额风险优先级不变。
- 第三、第五、第七周期才回本的本机独立延迟收益，以及窗口外才回本的反例。
- 较深假设中的收益依赖目标仍存活；队友提前击杀/改变目标/资源后，当前投资的机会成本。
- 本机当前防御必须成立的反例，队友补防或不补防不应被当成保证。
- 队友操作改变随机事件的消耗次序：同 seed 不等于同事件轨迹。
- 首动作相同而远端后缀不同、不同首动作在相同评价时点确有改善、只有同分项变化三者分开。
- 小预算根本到不了 5/7/9 的退化；扫描、浅层保护或重复后验挤占原预算的反例。
- 外部选择、额外玩家回合、终局早于窗口，以及完整用药资格。
- 前轮 F10 机会成本和 F12 假改善，不能为了通过而事后增加总席位或改质量口径。

人为注入队友动作只能作为可证伪扰动实验，不构成真人行为概率。没有校准数据时不得编造逐回合置信度、概率折扣或“安全概率”。深层坏后缀不应否定同首动作的全部其他续行；选择更短窗口也不能偷偷屏蔽原来已观测到的死亡/超额。

## 实施约束

- 只改多人政策及显式多人入口；官方单人 `0e6cc2d / 0.41.0` 原路径、参数、评分、能力承诺、预算和缓存保持原样。
- 所有策略值来自冻结根或分支；不读后台 live 值，不修改真实战斗。
- 复用当前模拟、路径诊断、三通道 Beam、最终批次和请求预算。没有证据不引入新搜索器、长期树、队友策略模型或可调参数框架。
- 探测或扩展也受同一次请求预算与取消约束；不能以更大 Beam/节点/时间掩盖问题。
- 不用未兑现估值抵扣风险或当作实际伤害；不改变每周期 3 HP 账本、风险次序、药水资格与真实终局事实。
- 窗口政策与资源语义分开。若所需原生消费者语义尚未证明，指出最小差分；不要在研究脚本里冒充已验证。
- 本轮不发布、不推送、不启动可见 Steam；不把 headless 数据写成联机胜率或可见性能。
