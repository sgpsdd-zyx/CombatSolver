## 1. 用户要解决的问题

用户说“当前多人策略，对长线收益判断很垃圾”，指的是本机建议经常立即防守或立即输出，错过需要先付能量、星能、格挡、生命或回合机会，之后才在同一战斗中兑现的路线。重点不是让求解器无条件喜欢所有能力牌，而是让它在满足当前安全边界和真实可兑现条件时，不要在兑现前把路线剪掉。

至少覆盖以下机制族；可以增补，但不能只挑最容易的一个：

- 故障机器人：黑暗球/黑暗增长与延迟激发（以当前游戏实际卡牌和模拟状态为准），并与集中、球位、推球和敌方血量联动区分。
- 储君：星能获得、星能花费、群星之子/黑洞/创世纪/封印王座等星能触发路线；区分“获得星能”与“花费星能”的事件，不把星能数量直接平方。
- 至少两类普通能力：先付费后每回合收益（例如额外能量、持续力量/集中、永久格挡/覆甲、抽牌或消耗引擎），并包含一张当回合容易被判断为负收益的能力。
- 至少一类即时可兑现的能力作为控制组，证明长线保护不会让明显不该开的能力泛化进入路线。
- 至少一类带风险或反协同的能力（例如集中递减、球位改变、自伤、耗牌或结束回合），证明模型不会只按名义收益奖励。

如果当前游戏中的名称与上面例子不同，请使用源码/本地化中的正式名称，保留用户原始描述并明确映射。不能凭卡名猜效果；读不到游戏 DLL 时说明缺口。

## 2. 必须先回答的定位问题

每个实验都要标出长线路线第一次消失的位置：

1. 合法动作/目标/选择根本没有生成；
2. 父内分支容量或选择链先丢掉；
3. 三通道 Beam、去重、转置、支配或完成池压缩丢掉；
4. 路线仍在但中间排序没有保住；
5. 路线到达终局但最终比较没有兑现收益；
6. 共同周期/七周期边界不足，或真实模拟语义与预估不一致；
7. 只是固定预算不够，不能误称评分错误。

不能用“提高能力牌权重”替代定位。每个结论必须给出：同根输入、动作前缀、第一次消失的阶段、实际工作量、对照路线和最小可复现数据。

## 3. 实验设计要求

请实际运行标准库抽象实验；如果当前环境能编译 `CombatSolver` 和 `OfflineSearchHarness`，再运行最小生产合同。没有游戏 DLL、失败战斗包或真实联机环境时，明确标成未验证，不伪称已改善胜率。

### 3.1 固定对照

对每个机制至少比较以下变体，使用同一根、同牌序/RNG、同一 DOP、同一节点/时间预算和同一终局政策：

- A：当前多人基线（生产现状）。
- B：只恢复/启用已经存在的多人可读长线事实，但不改变候选席位或预算；用于区分“事实已算但没消费”和“事实根本不存在”。
- C：一种多人专属、边界兑现的候选保护方案（由你设计），只在存在合法兑现窗口时保护少量代表；不能复制单人 `PowerCommitment` 或把单人评分带进多人。
- D：如果提出新的尾值/差分/短 rollout，必须与 A/B/C 同预算比较，并包含退化控制组；不能只跑更大预算。

至少报告：首动作是否变化、能力路线是否进入候选/保留/最终选择、实际完成敌方周期、累计本机扣血、逐周期超额、队友存活、敌方有效生命、药水与动作数、expanded/transitions/choice branches、各剪枝计数和总预算消耗。时间只作辅助，不用更快代替质量改善。

### 3.2 最小抽象树

构造至少 8 个小树，其中包括：

- 一条先打能力、第二/第三个敌方周期才回本的路线；
- 一条先打能力但永远没有兑现窗口的路线；
- 一条能力带风险（集中递减、球位损失、自伤、耗牌或结束回合），即时攻击/防守是安全对照；
- 一条星能获得后再花费的路线；
- 一条星能花费带来格挡或黑洞伤害的路线；
- 一条黑暗球先积累、晚一周期激发的路线；
- 一条同首动作但后续一个可兑现、一个不可兑现的分支，验证不能把坏后缀风险传播成首动作黑名单；
- 一条即时能力控制组，验证长线保护不会抢走真正更好的当前动作。

抽象树必须固定工作量，给出节点/边/终局重放成本；不能只列最终分数。所有收益都必须来自已模拟事实或明确的有界兑现上限，不允许给未知真人队友行为加乐观概率。

### 3.3 生产入口实验

如果能运行生产宿主，请至少增加或复用一个多人专属合同，证明：

- 能力牌和球/星能动作实际可合法生成、模拟并继续到兑现周期；
- 前缀在第一次 Beam/父内裁剪后仍能被观察到，或明确证实它在更早阶段丢失；
- 共同周期比较只奖励已经完成的真实事实，不奖励尚未兑现的名义估值；
- 结果仍是手动建议；多人设置、长线实验字段和缓存不进入单人请求；
- 同一输入下单人入口零进入，多人策略改动前后单人代表哨兵完整动作/状态/选择/RNG 不变。

至少选择一个机器人黑暗球场景、一个储君星能场景和一个普通能力场景。若真实游戏场景无法构造，交付可运行的生产函数合同和明确的缺失证据，不要用历史合同冒充本轮通过。

## 4. 候选算法必须比较

请独立比较，不预设一定采用某个方案：

1. 当前三通道 Beam + 长线事实补齐；
2. 有界能力/资源承诺席位或替换席位；
3. 同一根上的短差分/短 rollout（只到下一个或两个敌方周期）；
4. 固定首动作的延迟兑现后验；
5. best-first/UCT/PUCT/信息集方法等更换搜索器；
6. 纯调权重或扩大 Beam/节点/时间作为对照。

对每个方案写明：能修复哪一类首次丢失、不能修复哪一类、额外工作量、内存/取消/重放风险、是否会奖励未兑现收益、是否能保持真人队友未知边界，以及为什么不把单人策略带入多人。首批最多推荐一个最小生产改动和一个可回滚实验，不得一次建立第二个 Planner。
