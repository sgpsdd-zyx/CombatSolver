# 多人十四周期与计算额度对照

日期：2026-09-20。用户明确提出多人怪物高血量、战斗较长，愿意用更多计算时间换取更多回合的伤害规划，先尝试十四回合。本轮直接实现并验证这个范围，版本为 0.43.2 本地准备版，不包含新的外部发布授权。

固定基线为 fork 0.43.1 的 Release DLL（发布源码 `56b8ad4e`，本轮开始 HEAD `fa11efa6` 仅补发布文档），官方单人基线仍为 `cccc270 / 0.43.0`。证据现场 `.local/mp-fourteen-20260920/`。复用[旧窗口研究](pro-horizon-20260919/README.md)的真实模型、外部评价协议及负面证据，没有重新请求 6 Pro，也不把旧抽象实验算作本轮执行。

## 采用范围

- `MultiplayerSearchPolicy` 的默认上限从 7 改为 14 个敌方周期。额外玩家回合仍不增加敌方周期计数。
- `ResolveSearchProfile` 由协调器的既有多人入口调用一次；普通手动请求的时间与节点上限各乘二，整数极值饱和到 `int.MaxValue`。固定预算或显式时间覆盖保持原值；重复应用多人政策不再次倍增。默认中档从 120 秒 / 120,000 节点变为 240 秒 / 240,000 节点。
- `Phases` 通过多人政策按前沿最浅已完成敌方周期分摊剩余额度，保留每层至少 250ms / 500 节点、全局节点/时间终止及增量验证旁路。单人继续官方普通/首领的 4/8 玩家回合层，不调整共享常量。
- 结果保存本次有效时间和节点上限，UI 详情从只读结果投影，中英模板同步。窗口上限、选中路线深度与共同比较周期继续分开。

没有改变评分、三通道保路、风险顺序、每周期 3 HP 账本、药水资格、共同周期比较或完整动作数末级同分项。没有扩大 Beam、并行度、动作分支或 No-GC 配置。没有主动队友模型、自适应窗口、第二次搜索或跨请求树缓存。

## 窗口质量对照

`--multiplayer-review-contracts horizon-fourteen`：七个固定根，每根 H7/H14 各一次，Beam8 / 350 节点 / 3000ms / DOP1。仅执行所选首回合动作，再用相同的每回合一次合法攻击协议推进到第十四敌方周期或提前终局；外部评价工作不算搜索已获得的证据。为了区分首回合二选一，沿用旧研究的显式 Ethereal 铺垫牌改造、单攻击牌和缓冲状态；不是正常卡组质量的随机样本。

| 根 | H7 首动作 | H14 首动作 | 同一十四周期评价边界的敌方 HP（H7 / H14） |
|---|---|---|---|
| 早期回本 | 铺垫 | 铺垫 | 396 / 396 |
| 第七周期回本 | 铺垫 | 铺垫 | 344 / 344 |
| 第九周期回本 | 攻击 | 铺垫 | 304 / 292 |
| 第十四周期才回本 | 攻击 | 铺垫 | 164 / 162 |
| 短战斗 | 攻击 | 攻击 | 均第二玩家回合结束战斗 |
| 队友终结扰动 | 铺垫 | 铺垫 | 不主动出牌时均第六玩家回合结束；固定队友动作下均第二回合结束 |
| 仅 4 个节点 | 攻击 | 攻击 | 416 / 416，搜索均只完成共同周期 1 |

在后期才回本的两个根，H14 的首动作在相同外部协议下分别多造成 12 和 2 点伤害。长线根的搜索工作从 101 次展开 / 152 次转移变为 241 / 362。更深窗口也有成本：短战斗虽然首动作不变，展开仍从 57 增至 135；这里没有新增多人提前停止策略。

`horizon-baseline/` 与 `horizon-candidate/` 分别在旧/新 DLL 下执行上述输入。它们的首动作、非时序展开/转移、选中周期和外部结果保持一致，说明新增分摊在这些简单根上没有改变结果；它们没有触及层份额。四节点根再次说明上限十四不等于完成十四。

队友扰动沿用合法手动攻击，作用于外部评价器，不注入生产候选。旧研究已证明提前结束战斗可能使长线投资失效；本轮未建立真人行为概率或“十四优于七”的普遍结论。

## 计算额度与层分配

`horizon-budget` 使用双玩家、本机索引 1、十张原版卡组成的抽牌/生成牌输入、10,000 HP 敌人及双方 64 层缓冲。依次运行 H7/原额度、H14/原额度、H14/双倍额度；每次搜索共享相同冻结根，结束后核对 live 完整状态未变。动作和展开周期分布保存在 JSON。

| 对照 | 原额度 | H7 原额度 | H14 原额度 | H14 双倍额度 |
|---|---|---|---|---|
| 旧分配，Beam24 | 1200 节点 / 3000ms | 完成 7 周期，1148 展开 | 1200 节点用尽，选中 7 周期 | 完成 14 周期，2342 展开 |
| 新分配，Beam24 | 同上 | 同上 | 同上 | 同上 |
| 旧分配，Beam96 | 7000 节点 / 5000ms | 完成 7 周期，4355 展开 | 7000 节点用尽，选中 11 周期 | 完成 14 周期，8919 展开 |
| 新分配，Beam96 | 同上 | 完成 7 周期，4316 展开 | 7000 节点用尽，选中 12 周期 | 完成 14 周期，8919 展开 |

Beam96 同额度的新分配得到更多已计算周期，但不能拿十二周期的累计伤害与十一周期直接比较成输出提升。双倍额度完成十四周期时，两种分配的终点敌方 HP 同为 9234；Beam24 为 9269。Beam8 初始探针原额度就已足够，因此加倍没有增加工作，结果保持一致。

这些数据支持给更长窗口额外额度，并将多人预算分摊从单人回合层中独立解释。它们不证明任意牌组都能达到十四周期，也不证明深度增加时首动作必然更好。墙钟只保留原记录：启动/JIT、同进程冷热与部分构建并行干扰明显，未做可见性能实验，不据此报告提速倍数或实际等待时间。

最终多人合同使用 FOGMOG_NORMAL、Beam12 / 700 节点 / 12000ms / DOP2。十三次原生完整多人 `ContinuationStamp` 与预测全文一致，包含双方牌堆、资源、能力、怪物状态、历史与 RNG；第十四敌方周期形成明确边界，显式 H7 对照也按各自上限停止。搜索返回 44 动作、十四回合建议，旧前缀重验 1 动作。额外回合、本人/队友选择、四张多人卡、队友药水、强制/保护指令及禁止自动操作保持通过。

同一合同核对生产协调器的双倍请求、显式预算、重复 Apply、整数饱和和实际 UI 预算文本。九个既有扣血案例，以及救援、铺垫、未来风险、最终资格/排序/排列、增量回放与 Fork 哨兵通过。
