# 多人伤害归属审视：实验与采用（2026-09-23）

[返回策略索引](../README.md) · [现役多人指南](../../multiplayer-advisor.md) · [结构化证据](implementation-evidence.json) · [知识归档](closeout.md)

## 1. 结论与边界

用户要求充分实验并实现原[静态审视](../multiplayer-race-model-review-20260922.md)中可取之处。本轮基于 `cad3ba35`，其行为仍为已发布 `86026b05 / 0.44.1`；单人基线保持官方 `42e09028 / 0.44.0`。实现提交 `fd976376` 已完成本地 0.44.2 的 Release 构建与最小 ZIP，未创建标签、推送或发布；阶段凭证见[本地定版记录](../../releases/0.44.2-PREPARE.md)。

采用一项：原生伤害历史中没有 dealer 的实际敌方扣血，按阶段参与人数均分后参与多人选路。它能为毒等持续效果提供合理的选路价值，但不虚构本机归属，不支付个人目标，也不生成个人达标见证。原生毒的结算语义没有修改。

另外两项独立原型在这些简化实验中没有观察到选路收益，已从生产代码删除：按距离降低闲置队友死亡代价、按怪物威胁加权剩余血量。这不足以证明两种思路在真人配合下无效。没有整体替换为历史团队速率竞速模型，没有缩短十四周期，也没有用 ready 推断队友不会再行动。

证据结论分开阅读：原生差分证明已测伤害结算与状态所有权；合成脚本对照证明若干指定局面的首轮建议收益。当前没有“真人队友持续操作后，玩家按新建议继续整场”的质量证据，不能据此估计联机胜率。

## 2. 对原审视的定向复核

| 论点 | 本轮证据与处理 |
| --- | --- |
| 毒没有获得本机贡献信用 | 成立。补读原生 `PoisonPower.Trigger`：伤害命令没有 dealer；混合本机/队友毒的原生全队差分也确认 null dealer。保留真实归属，补充独立选路折算。 |
| 总伤害减本机伤害就是队友伤害 | 不成立。差额还包含无来源扣血；它不能直接用作队友历史输出。新增原始无来源计数，绝不把它改成队友或本机伤害。 |
| 历史团队速率是测量，不是预测 | 历史值是测量，将其延续到未来就是预测。一次性爆发、慢启动、转火、治疗和初回合分母都需额外模型；在“不预测队友主动操作”的约束下未采用。 |
| 全体受击意味着防守互相独立 | 过强。补读原生 `Intercept`、`CoveredPower`、`InterceptPower`，覆盖与伤害转移会耦合玩家防守。当前模拟的该效果还会显式返回 `UnsupportedEffect`，不混入本次评分修复。 |
| 任意共享 RNG 消耗都会改变后续抽牌 | 过强。补读 `RunRngSet`：九条流分别创建；共享 `CombatTargets` 不等于消耗 `Shuffle`。同一条流上的队友操作仍可使条件推演与实机分叉。 |
| ready 后队友本回合不可能再行动 | 不成立。原生 `UndoReadyToEndTurn` 可撤销。无头实测 ready/撤销均有效；因此未将 ready 变成候选合法性、缓存身份或“确定不行动”承诺。 |
| 十四周期没有可信用途 | 不能据此整体缩短。七根 H7/H14 重跑保留了晚回本例 84→104 伤害、0 战损的差异；更晚回本未选中也保留为局限。 |

上述补读仅定向访问本机游戏 `0.111.0` 的反编译内容。全体受击、多人 HP 缩放、死亡不立即结束整场战斗本身没有被推翻；本轮不声称审计了全部怪物、辅助效果或网络时序。原文作为历史输入保留，不回写成实施结果。

## 3. 实际评分与状态所有权

记阶段初始敌方有效生命为 `H0`，当前有效生命为 `H`，阶段内本机实际扣血为 `L`，全体实际扣血为 `T`，其中 dealer 为空的扣血为 `U`，阶段参与人数为 `n`。观察到的真实增量与当前分支增量分别累加：

```text
personalProgress = L + min(0, H0 - H - T)
scoredProgress   = L + U / n + min(0, H0 - H - T)
deficitCost      = max(1, rootLocalHp) * clamp((target - scoredProgress) / max(1, target), 0, 2)^2
```

`U / n` 使用浮点分数，不逐次截断。例如三人共享 1 点伤害得到 `1/3`，不是零。敌人治疗、复活和新增生命仍可冲回进展；同回合多次重算从阶段起点计算，不能重复领信用。人数变化显式重建账本，保留原阶段截止。无来源计数不能为负、回退或超过 `T - L`，异常显式失败。

这是一条评分规则，不是实际伤害分配。所有玩家/怪物的生命、毒层数、伤害事件、下一行动与九条 RNG 仍按原生模拟结算。已知队友 dealer 的伤害永远不会进入 `U`。清场仍按真实敌人生命判断，个人达标仍只读 `personalProgress`。

中间评分、固定阶段比较和条件尾值使用同一折算口径。前沿支配额外核对实际多人目标代价，避免旧的“个人贡献更高”坐标删除更有价值的共享伤害路线。用药资格、近期死亡次序、队友死亡代价、三周期截止、4B 前沿、十四周期上限、普通双倍/固定原值预算都保留。

| 层 | 改动与所有权 |
| --- | --- |
| Runtime | `MultiplayerContributionCapture` 从原生 `DamageReceivedEntry.Dealer` 捕获 `UnattributedDamage`；`MultiplayerContributionSession` 保存阶段起点与观察增量。worker 不读取 live 历史。 |
| 分支 | `RecordDamageReceived` 只累加原始 null-dealer 敌方扣血；`AdvisorUnattributedDamage` 按值 Fork，根和兄弟互不修改。 |
| Search | 计数进入快照、不可变周期检查点、去重/转置标签和严格增量对账；不加入战斗状态键或原生 `ContinuationStamp`。`MultiplayerContributionObjective` 持有折算函数。 |
| UI | 只读 `AdvisorySharedDamageCredit`，中英提示其参与选路但不计本机贡献；零值隐藏。达标文案、个人实绩及预计贡献仍使用严格归属。 |
| 实验宿主 | `race-dev` / `race-holdout` 只保留 0/1 开关；2/4/7 原型仅存档。`shared-ranking` 专门检查前沿、缓存及中英投影。 |

## 4. 实验协议与结果

先冻结旧 DLL，再以同根、固定 `Beam12 / 350 节点 / 3000 ms / DOP1` 比较。原型包含五组：原策略 0、共享伤害 1、队友死亡折价 2、威胁压力 4、三项合并 7。八个开发根、四个留出根共 60 次原型搜索；其中 Intercept 根不能作为辅助语义通过证据。最终精简实现另有五组 0/1 成对检查，共 10 次搜索；冻结旧 DLL 另跑一次毒例校准关闭开关。合计 71 次变体搜索，另有 14 次窗口比较；不是 85 场独立真人战斗。

每条返回路线只取本回合动作，之后本机按固定“能打则先防御、再能力、再 ID”的规则续行，最多五个敌方周期。队友使用闲置、每周期一张防御、每周期一张打击三种固定脚本，遵守牌堆/能量/目标合法性。脚本只注入外部评价器，搜索器始终看不到未来队友主动操作。外评与搜索预算分别记账，质量读模拟结算后的 HP/存活/结束周期，不用被改动的评分自证；但外评和搜索共用模拟引擎，仍可能共享语义偏差。重复种子、脚本和原型变体不能当作独立样本扩大显著性。

这些根清空并重建了牌堆、遗物、能力与药水，部分为跨角色合成手牌；队友只有少量固定牌。队友动作集中在本机结束回合的边界，未覆盖逐牌交错、临时转火、爆发/蓄力切换、搜索期间继续操作和手动重算节奏。后续本机动作来自固定规则，不会重新捕获根并再次请求军师。本机死亡或评价步数/周期耗尽也会停止外评，因此 `won=false` 不等于全队战败，五周期余血不等于最终战损；不同怪物标签、新种子和同根 HP 变体也不代表独立真人样本。

下表伤害/战损数值取队友防御脚本；三个收益根在另外两种脚本下方向相同，完整结果见 JSON。

| 根 | 原策略 → 共享伤害 | 模拟外评 |
| --- | --- | --- |
| 开发毒，敌人 120 HP、本机 80 HP | `STRIKE_IRONCLAD` → `DEADLY_POISON` | 五周期敌人余血 46→31，本机同损 16 HP，队友同血。 |
| 新种子高血毒，敌人 180 HP、本机 67 HP | `STRIKE_IRONCLAD` → `DEADLY_POISON` | 五周期敌人余血 106→91，本机同损 16 HP，队友同血。 |
| 新种子低血毒，敌人 55 HP、本机 32 HP | `STRIKE_IRONCLAD` → `DEFEND_IRONCLAD` | 都在第四周期结束，本机损失 16→12 HP；队友攻击脚本都在第三周期结束，损失 10→6 HP。 |
| 低血防御哨兵，本机 6 HP | 首动均 `DEFEND_IRONCLAD` | 首动不退化；固定后续脚本在闲置/防御队友下仍会死亡，不能称整场安全。 |
| 能力投资哨兵 | 均 `INFLAME, STRIKE_IRONCLAD` | 五周期同损 22 HP、敌人余血同为 97。 |
| 四个原型留出根 | 各变体首轮动作均相同 | 毒刃、慢启动、低血队友及多敌威胁未增加收益，不宣称普遍提升。 |

原型中的队友死亡折价和威胁压力没有改变所观察到的首轮动作及外评结果，合并组的已观察收益全部来自共享伤害。这是当前夹具未检出收益，不是对两种思路的普遍否定；没有凭“理论合理”将它们保留为生产开关。

辅助负对照中，`LIFT` 单卡可在首周期保住 2 HP 队友，打击和自保防御不能；所有原型都保留 `STRIKE_IRONCLAD,LIFT`。它只能证明当前明确辅助见证未被删掉，不能证明队友长期不死。`INTERCEPT` 看似保住队友却返回 `UnsupportedEffect`，必须排除该部分结果；首次 Lift 夹具遗漏 AnyPlayer 目标后已修正，错误运行不算通过。

窗口对照固定七根，各用 H7/H14：晚回本 `late_setup` 由攻击转为能力，外部十四周期伤害 84→104、0 战损；短战斗、四节点预算、队友一次爆发保留。`payback_seven/nine/fourteen` 仍不选投资，`NOXIOUS_FUMES` 代表也仍不选能力。这些是明确未解决项。

## 6. 未做与复现

未验证真人联机、三/四名真人操作、全角色/全遭遇质量、可见 Steam 性能、长期胜率、干净安装或完整发布门禁。三人测试仅覆盖分数与账本。当前仍会受闲置队友条件、有限 Beam 与有限阶段窗口影响；没有证明“十四周期最优”或“所有持续伤害流派更好”。不增加预算掩盖差异。

现役入口、参数和外评脚本说明见[离线宿主](../../OFFLINE_SEARCH_HARNESS.md)。`RACE_FIXTURE` 指定一个根，`RACE_VARIANT=0/1` 关闭/开启共享信用；两个新种子根另外设置 `RACE_ENEMY_HP=180,RACE_LOCAL_HP=67` 或 `55,32`。每个实验根独立进程，禁止把不同根的牌堆、历史或敌人残留串起来。原生请求位于 `coverage/unattended/multiplayer-shared-damage.json`，原有 Bash/PowerShell 启动器均可读取，必须使用实例清理开关。

被拒绝原型的[说明与快照](prototype/README.md)保留用于审视当时实现；生产不加载它们。后续若继续研究，先补齐 Intercept 公共语义，再另取独立根评估辅助价值；历史团队速率需要明确预测授权与独立质量验证，不能仅改名字规避约束。
